# Adapting features for new data without catastrophic forgetting

Read from arXiv PDF text (pdftotext) on 24 Oct 2026: mechanisms, algorithm boxes, hyperparameters and result tables were read in the text; long appendices and per-figure curves were searched, not read line by line. Numbers are quoted from the paper text. "UNVERIFIED" = not confirmed in a paper text we could read (for example the Nature Communications metaplasticity paper and the PNAS XdG paper are not reachable; only the 3-page arXiv summary of the first was read). Tags DERIVED are our arithmetic or reading, not paper claims. Benchmark scenarios matter: almost every paper below reports TASK-incremental results (task id given at test, or one head per task). That does NOT transfer to our case (no task id; a new class must be recognised against all old classes). Where a paper gives a class-incremental row it is flagged CLASS-IL.

Our target (for the reader): a frozen unsupervised sparse binary detector layer feeding an integer counting table, no multiplies, no dense matrices. A new class with 20 to 100 examples reaches 66 percent recall (vs 91 for a CNN with replay) because the detectors cannot adapt.

## 1. FlyModel: "Algorithmic insights on continual learning from fruit flies" (Shen, Dasgupta, Navlakha; arXiv 2107.07617)

Mechanism, exact.
- Input x in R^d (pre-processed features; they use a frozen pretrained encoder, so the FEATURES are NOT adapted either).
- Layer 1, frozen: sparse binary random matrix Theta (m x d), each KC samples about 0.1 d of the d inputs (ones in random positions). psi = Theta x. Winner-take-all: keep the top l entries, set the rest to 0 (fly: l = 100 of 2000, 5 percent). Min-max normalise phi to [0,1]. "The matrix Theta is fixed and not modified during learning; i.e., there are no trainable parameters in the first layer."
- Layer 2, associative, all-to-all KC to k class units, weights w_ij in [0,1]. Update on input x with target j: w_ij = (1 - alpha) w_ij + beta * phi_i for j = target; w_ij = (1 - alpha) w_ij otherwise. Experiments set alpha = 0 (no forgetting term), so non-target weights are untouched ("partial freezing": only synapses from the ACTIVE KCs to the TARGET class change). Weights capped to [0,1].
- Prediction: class with largest sum_i w_ij phi_i (argmax over MBONs; read from the model description, DERIVED).
- Learning is applied on every example, correct or not (associative, not error-driven). The perceptron variants that decrease weights of the wrongly predicted class, or learn only on mistakes, forget more (Perceptron v1 to v3 vs v4 = FlyModel); Lemma 2 in the supplement shows decreasing weights lets shared KCs be "hijacked" by the most recent class. Lemmas 3, 4 and Theorems 5, 8: the MBON weight vector converges to the class mean scaled by a constant.

Hyperparameters. MNIST-20: learning rate 0.01, m = 3200 KCs, input 84 features (LeNet5 trained on KMNIST, penultimate layer), each KC sums 10 randomly chosen PNs, l = m/k with k = 20. CIFAR-100: learning rate 0.2, m = 20000, 512-d ResNet18 (ImageNet-pretrained) features, each KC sums 64 PNs, k = 100. Hidden layer about 40x the input.

Protocol. CLASS-IL, single pass (one epoch), MNIST-20 = MNIST + Fashion-MNIST (20 classes, 10 two-class tasks: 0/1, 2/3, ...); CIFAR-100 in 25 tasks of 4 classes; evaluation after each task on all classes seen so far, no task id.

Exact rows (MEASURED by the authors).
- MNIST-20 after 5 tasks (10 classes): FlyModel 0.86 +- 0.0006; BI-R 0.77 +- 0.02; GEM 0.69 +- 0.02; EWC 0.58 +- 0.10; Vanilla 0.19 +- 0.0003.
- MNIST-20 end of training (20 classes): FlyModel at least 0.19 higher than any other method and only 0.11 below the Offline upper bound; ablation text gives FlyModel 0.75 (sparse + partial freezing) vs 0.54 (sparse + logistic regression); sparse-code models avg 0.64 vs dense-code 0.07.
- CIFAR-100: FlyModel at least 0.15 above every CL method, 0.13 below Offline; ablation 0.41 (FlyModel) vs 0.21 (sparse + logistic regression).
- Average memory loss across tasks: FlyModel 0.07; GEM 0.24; EWC 0.27; BI-R 0.42; Vanilla nearly 1.
- No Split-MNIST/Split-FMNIST/Split-CIFAR-10 rows (other splits). UNVERIFIED whether code gives these.

Storage: k x m weights (3200 x 20 = 64,000 for MNIST-20). Replacing real weights by small integer counters is DERIVED (our chip already does this). Multiplies: none in learning (add beta*phi; with binary phi and beta power of two this is a counter increment).

Failure modes (from paper). Weights only grow with alpha = 0, so saturation in the long run (they say most did not saturate in tens of thousands of steps; a small alpha may be desired); dense codes break it (0.07); input representation quality is the limit (all gap to Offline is representation); it adds no new KC features: a class whose evidence is not captured by the fixed Theta stays at the representation ceiling. This is exactly our 66-vs-91 gap (DERIVED).

## 2. Recruitment and growth of new units

### 2a. Dynamically Expandable Networks (Yoon et al., arXiv 1708.01547, ICLR 2018)
Mechanism. Three steps per task t: (1) Selective retraining: L1-regularised training of the top layer, then find the subnet of units connected to the new output by BFS and retrain only that subnet. (2) Dynamic expansion: if loss after (1) is above threshold tau, add k units per layer (top-down), train with group-sparsity, drop units that turn out unnecessary (two parameter-matrix expansions W^t = [W^{t-1}; W^N]). (3) Split/duplicate: for each hidden unit i drift rho_i = ||w_i^t - w_i^{t-1}||_2; if rho_i > sigma, duplicate the unit (old copy frozen for old tasks), retrain. Timestamped inference: unit created at task t is not used by tasks before t.
Storage: new unit weights + one timestamp per unit. Multiplies/dense: yes (dense nets, L1 sparse retrain), but the DECISION rules (loss above tau, drift above sigma, timestamp) are threshold comparisons.
Protocol: task-incremental, one-vs-rest binary tasks (MNIST-Variation 62,000 images with rotation and noise; CIFAR-100 with 10 subtasks per task; AWA 50 animals, DECAF features, 30/30/30 split). NOT class-IL.
Rows (read from figure legends in the text, mapping of panels is DERIVED, treat as UNVERIFIED): average per-task performance on MNIST-Variation DEN 0.8131, DNN-Progressive 0.7817, DNN-EWC 0.7480, DNN-L2 0.7440, DNN 0.6785, DNN-STL 0.7963, DNN-MTL 0.8047; a CIFAR-100 panel shows DEN 0.9225.
Failure modes: needs thresholds (tau, sigma) tuned; threshold on loss needs labels; the paper itself says retrain/regularisation methods "cannot dynamically increase their capacity"; progressive nets struggle with T = 50 tasks.

### 2b. Learn to Grow (Li, Zhou, Wu, Socher, Xiong; arXiv 1904.00310)
Mechanism. Differentiable neural-architecture search over three choices per layer: "reuse" (same parameters, optionally fine-tuned), "adaptation" (a task-specific 1 x 1 adapter in parallel to the old conv; per-task overhead small), "new" (a fresh layer). Search on a split of the new data, then retrain. Old tasks use their stored architecture so no forgetting of reused-and-frozen parts. Benchmarks: permuted MNIST, split CIFAR-100, Visual Decathlon. Task-incremental. Numeric rows: not extracted, UNVERIFIED. Dense, conv, gradient-based NAS: no fit as an algorithm; the reuse/adapt/new vocabulary is useful for our design (DERIVED).

### 2c. Progressive Neural Networks (Rusu et al., arXiv 1606.04671)
Mechanism. One new column per task; earlier columns frozen; lateral connections U_i^{(k:j)} from every earlier column j < k feed layer i of column k. "The number of parameters grows quadratically" with columns (paper, line ~556). Task-incremental (a column per task, task id selects the column). Zero forgetting by construction, no memory-bounded design. DERIVED: quadratic growth makes it unsuitable for a fixed-size chip.

### 2d. Adult-neurogenesis-style recruitment
No single primary paper read for a binary-network version. The closest read-text analogues are DEN's expansion rule and FlyModel's fixed 40x expansion (which leaves silent KCs available). We found no paper in this set that grows a frozen sparse binary detector layer. UNVERIFIED claim that none exists. Our design (DERIVED, not a paper claim): keep a pool of spare unassigned detectors; when the counting table's margin signals novelty (margin low for samples of a labelled new class), assign spare detectors by copying a random binary mask whose bits are chosen from the new examples (e.g. bits that are consistent across the 20 to 100 examples), freeze old detectors, add count rows only for the new detectors.

## 3. Binary masks on a fixed backbone

### 3a. SupSup, "Supermasks in Superposition" (Wortsman et al., arXiv 2006.14769)
Mechanism. Fixed random backbone W (signed Kaiming constant: weights are +c or -c, biases 0, so only the seed needs storing). For each task i a binary mask M^i found by Edge-Popup (scores per weight, top-k by magnitude; or Mallya's threshold-0 scheme for MNIST): output p = f(x, W (.) M). Task id unknown at test: p(alpha) = f(x, W (.) sum_i alpha_i M^i), choose alpha to minimise output entropy H. One-Shot algorithm: inferred task = argmax_i ( - dH/d alpha_i ) (one gradient). Binary algorithm: log k steps, rule out half the tasks each step. Scenario NNs (no id even in training): if k * max_i nu_i < 1 + eps where nu = softmax(-grad H), treat the data as unseen and allocate a NEW mask, k += 1. HopSupSup stores masks implicitly as attractors in a Hopfield network of size about the base network.
Storage: 1 bit per weight per task, sparse masks stored in scipy CSC with 16-bit integers; base weights replaced by a seed. SplitImageNet GG: SupSup 88.68 percent avg top-1 at 100.98M bytes, a variant 89.58 at 195.18M bytes, 86.37 at 65.50M; BatchE (GG) 81.50 at 124.99M; upper bound 92.55 at 10222.81M bytes (labels of the rows are partly garbled in the text extraction; numbers quoted from text, assignment of the 89.58 and 86.37 rows to configurations is UNVERIFIED). Masking cost: "approximately 1 percent of forward pass time for ResNet-50 on a 1080 Ti" (elementwise product implemented as index selection).
Protocol: GG/GN/NN scenarios; GNu (task id in training only) on PermutedMNIST (2500 tasks, 25,000-way, One-Shot from a single image), RotatedMNIST, SplitMNIST (5 two-way tasks). In GNu output heads are shared sized l*k. Split MNIST is task-IL-with-inferred-id, results are in figures; no per-class Split-CIFAR/class-IL table. SplitMNIST accuracy numbers: UNVERIFIED.
Multiplies: inference is masked-weight forward (multiplications by +-c, which are sign flips); mask learning needs backprop; task inference needs a gradient through the whole net (dense).
Failure modes: tasks that are similar (10-degree rotations) need a full batch and the Binary algorithm to be told apart; a single wrong task inference gives accuracy 0 for the batch; the whole approach assumes one mask per task, not per class; capacity of a fixed random backbone.

### 3b. Piggyback (Mallya, Davis, Lazebnik; arXiv 1801.06519)
Mechanism. Keep real-valued mask weights m_r per backbone weight; binary mask m = 1 if m_r >= tau else 0; layer output y = (W (.) m) x with W frozen ImageNet-pretrained; gradient through the threshold by straight-through: dE/dm = (delta_y x^T) (.) W (Eq. 7). Real masks discarded after training; one binary mask per task. tau = 5e-3, mask init 1e-2 (paper). Overhead "1 bit per network parameter" per task = 1/32 = 3.12 percent of the 32-bit backbone per task. Task id required at test (switch mask). Task-specific BN parameters help (WikiArt top-1 error improves, about 1 MB extra). Rows: errors per dataset in Table 2 (ImageNet-pretrained VGG-16); not transcribed here (UNVERIFIED); text states piggyback errors are "slightly lower than the individual network case" and independent of task order, unlike PackNet. Failure: needs a strong pretrained backbone ("well-initialized backbone is crucial"), float multiplies in the base forward, task-IL only.

### 3c. PackNet (Mallya and Lazebnik; arXiv 1711.05769)
Mechanism. Train task I, prune a fraction of weights (smallest magnitude; 50 or 75 percent), retrain the survivors, freeze them; the pruned (zero) weights are freed and trained for task II; prune again, retrain; and so on. At test the mask of the chosen task reconstructs the exact network (task I mask: gray weights only; task K mask: weights of tasks 1..K). No forgetting by construction. Storage: a parameter first used by task K is used by all tasks K..N, so "at most log2(N) bits to encode the mask per parameter, instead of 1 bit per task, per parameter". VGG-16 (537 MB): overhead about 17 MB for one added task, about 34 MB for three tasks. Rows (Table 2/3, ImageNet then Places365): ImageNet top-1 error 28.42 (individual), 29.33 (prune 50 percent), 30.87 (prune 75 percent), jointly trained 33.49; Places365 top-1: individual 46.35, 50 percent 47.44, 75 percent 46.99, jointly trained 45.98. Task-IL only; capacity runs out ("begins to suffer when more than 3 tasks are added"; order sensitive, errors rise 4 to 7 percent when a task is added last instead of first, from the Piggyback paper's comparison).

## 4. Soft gates and context selection of sparse subnetworks

### 4a. HAT (Serra et al.; arXiv 1801.01423)
Mechanism. Per layer l and task t a learned embedding e_l^t; attention a_l^t = sigmoid(s e_l^t) applied to unit outputs (units = neurons or conv filters). Annealing: s goes from 1/smax to smax within each epoch (Eq. 3: s = 1/smax + (smax - 1/smax)(b-1)/(B-1)); at test s = smax so a is almost 0/1. Cumulative mask a_l^{<=t} = max(a_l^t, a_l^{<=t-1}) (element-wise). Weight gradients are scaled by 1 - min(a_{l,i}^{<=t-1}, a_{l-1,j}^{<=t-1}) (the "hard attention" gradient mask); embeddings get a compensation factor. Regulariser promotes low capacity usage (weighted normalised L1 over a^t; parameter c). Defaults smax = 400, c = 0.75 (permuted MNIST: smax 200/400, c 0.5). Last layer is multi-head (task id picks the head). Storage: one embedding (binarisable to 1 bit) per unit per task, much smaller than a per-weight mask. Multiplies: float, dense. Class-IL: none (task id required; Table in the paper is forgetting ratio on task sequences); numbers beyond the settings above: UNVERIFIED. Benchmarks used in later papers: 5-Datasets 91.32 (HAT), CIFAR-100 10 tasks 72.06, miniImageNet 59.78 (as listed in GPM's Table 1, task-IL).

### 4b. Active dendrites (Iyer et al., arXiv 2201.00042) and XdG (Masse 2018)
Active dendrites mechanism. Each neuron has a feed-forward linear sum plus n dendritic segments u_j; with context vector c, the neuron's activation is modulated by the segment with the largest response: (W x + b) * sigmoid(max_j u_j^T c); then k-winner-take-all keeps only the top k units per layer. Only the winning segment gets gradient (others stay frozen). Context: one-hot task id (multi-task RL), or a task PROTOTYPE vector (mean of the task's inputs) picked at test by nearest prototype under Euclidean distance; if the task id is not given in training a clustering rule instantiates a new prototype when a batch does not match an existing one. 2,048 units/layer, 2 hidden layers on PermutedMNIST. Rows: PermutedMNIST accuracy 94.6 (10 tasks) and 81.4 (100 tasks) with context given in training; 94.3 and 76.9 with prototypes selected online; with SI: 97.2 and 91.6. Meta-World MT10: 87.5 percent vs MLP 76.6 percent success. Storage: segments are float vectors (T segments per neuron for T tasks), prototypes are float vectors. Dense matmuls. No class-IL rows.
XdG (Masse, Grant, Freedman, PNAS 2018): fixed random per-task binary gates on hidden units (about 80 percent of units gated off per task, combined with synaptic stabilisation). Full text not read; UNVERIFIED in details. The idea (task-dependent random sparse unit masks, 1 bit per unit per task, no learning of the gate) is the cheapest mask scheme in this note, DERIVED.
Failure modes: needs task context at test or a prototype inferred per example (error propagates); similar tasks give overlapping prototypes; units/segments scale linearly with task count.

### 4c. k-WTA with boosting, "How can we be so dense?" (Ahmad and Scheinkman, arXiv 1903.11257)
Mechanism. Layer output keeps only the k largest activations of a (possibly weight-sparse) layer. Boosting: a running duty cycle d_i(t) = (1 - alpha) d_i(t-1) + alpha [i in topIndices] (Eq. 6); boost b_i(t) = exp(beta (a_hat - d_i(t))) with a_hat the target active fraction (Eq. 7); selection uses boosted activations, output uses unboosted ones. beta = 1.0 or 1.5. Theory: for sparse binary vectors of dimension n with a active bits, the probability that two random vectors share at least b bits falls with n; the paper shows noise/interference robustness grows with n and with sparsity, with an overlap-probability formula over the "overlap set". Rows: MNIST (Table 1 as extracted) Dense CNN-2 96.37 +- 0.37 test, noise 8,730 +- 471; Dense CNN-2 with dropout 0.5 95.69 +- 0.48, 7,681 +- 368; Sparse CNN-2 96.65 +- 0.21, 11,233 +- 1013; Super-sparse CNN-2 96.57 +- 0.16, 10,752 +- 942 (row-to-table mapping UNVERIFIED). No continual-learning experiment in this paper; the link to forgetting is the interference argument, and the FlyModel ablation (sparse code 0.64 vs dense code 0.07 at the end of MNIST-20) is the continual-learning evidence (DERIVED). Boost needs one integer counter (duty cycle) per detector; boosting recruits under-used detectors, which is a ready-made recruitment rule for spare detectors (DERIVED).

## 5. Dual-memory and replay

### 5a. FearNet (Kemker and Kanan, arXiv 1711.10563, ICLR 2018) and Complementary Learning Systems
Mechanism. Hippocampus HC = probabilistic neural network over stored exemplars: P_HC(C = k | x) = beta_k / sum beta_k', beta_k = (eps + min_j ||x - u_{k,j}||_2)^{-1}. mPFC = autoencoder-regularised MLP (long-term). BLA = small network gating HC vs mPFC; final prediction combines. Sleep: for each learned class generate ceil(m) pseudo-examples from stored class mean and covariance via the decoder, mix with HC exemplars, fine-tune mPFC by backprop, then delete HC. Inputs are ResNet embeddings (features frozen again). Class-IL (one new class per session), CIFAR-100 (2048-d), CUB-200 (2048-d), AudioSet (1280-d). Offline MLP: 69.9 percent (CIFAR-100), 59.8 (CUB-200), 45.8 (AudioSet). Table 2 (Omega_base, Omega_new, Omega_all): FearNet CIFAR-100 0.927 / 0.824 / 0.947; CUB-200 0.924 / 0.598 / 0.891; AudioSet 0.962 / 0.455 / 0.932; means Omega_base 0.938, Omega_all 0.923. 1-NN: 0.878 / 0.648 / 0.879 on CIFAR-100, mean Omega_all 0.729. iCaRL mean Omega_all 0.782; GeppNet mean 0.759; FEL (fine-tune) 0.572. Oracle gate (Table 3): Omega_all 1.002 on CIFAR-100. Memory to train on CIFAR-100: FearNet 10.7 MB, iCaRL 17.6 MB, FEL 272.5 MB, 1-NN 4.1 GB; extrapolated to 1000 classes: FearNet 74.4 MB. Failure: Omega_new drops when BLA misroutes (0.824 vs oracle 0.912 on CIFAR-100); a new class seen in more than one session has no clean way to update its stored statistics (paper's own open question); pseudo-examples from a diagonal-covariance model degrade (Omega_base 0.942 / 0.781 for the 100 / 1000 class columns in its Table 6 as extracted, UNVERIFIED mapping).
CLS (McClelland, McNaughton, O'Reilly 1995): no PDF reachable; cited here only through FearNet's description (hippocampus replays recent memories during sleep so that cortex consolidates without interference). The original paper's numbers are UNVERIFIED.
Fit: the structure maps onto our design (DERIVED): the counting table is the fast store (and, unlike weights, never interferes), the sparse detector layer is the slow store; consolidation by replaying stored class statistics (mean binary code per class = a count vector) needs no backprop, only a replay of binary codes through the detector-adaptation rule.

### 5b. DualNet (Pham, Sahoo, Liu, Hoi; arXiv 2110.00175)
Slow learner: backbone trained by self-supervised Barlow Twins (n = 3 iterations between mini-batches) on the replay memory with a Look-ahead optimiser; fast learner: small CNN that outputs pixel-wise multiplicative coefficients m_l, h'_l = h_l (x) m_l / ||m_l||_2^2 (Eq. 6) on the slow features, trained per sample. Memory 50 samples per task (ring buffer). Benchmarks Split miniImageNet and CORE50, task-aware and task-free; no Split-MNIST/CIFAR class-IL tables; numeric rows not transcribed (UNVERIFIED). Floating, dense, multiplicative: poor fit; the idea of a slow unsupervised feature learner and a fast label-driven selector matches us (DERIVED).

## 6. Gradient projection family (dense linear algebra)

### 6a. GPM (Saha, Garg, Roy; arXiv 2103.09762)
Mechanism. After task t, run n_s samples through the net, build representation matrix R^l per layer (for conv, patch vectors), SVD, keep the smallest k such that ||(R)_k||_F^2 >= th ||R||_F^2 (Eq. 5). Bases M^l = [u_1..u_k] form the Core Gradient Space. For later tasks project gradients: FC: grad := grad - (grad M)(M)^T; conv: grad := grad - M M^T grad. Update: remove already-covered directions R_hat = R - M M^T R, SVD, add new bases satisfying the threshold (Eq. 9). Thresholds: PMNIST 0.95 first layer / 0.99 others; th grows 0.0003 per task for some runs.
Storage: float basis matrices; maximum GPM size (GPM Max): MLP (784, 100, 100) 0.63M parameters; AlexNet 5.84M; ResNet18 8.98M. PMNIST uses 69 percent of GPM Max. Multiplies: full SVD, projections, backprop.
Rows (task-IL, ACC / BWT): PMNIST GPM 93.91 / -0.03 (multitask 96.70, OWM 90.71 / -0.01, EWC 89.97 / -0.04); 10-split CIFAR-100 GPM 72.48 / 0.00 (HAT 72.06, EWC 68.80, OWM 50.94 / -0.30, multitask 79.58); miniImageNet 60.41 / 0.00 (HAT 59.78); 5-Datasets 91.22 / -0.01 (HAT 91.32). CLASS-IL (appendix D.3, Digits dataset, one MNIST class per task, no task hint): GPM ACC 70.67 BWT -0.26; EWC 10.00 / -1.00; DGR 59.60 / -0.43; DGDMN 81.80 / -0.15. The authors state class-IL "inevitably" needs some old-data replay. Failure modes: capacity: bases fill the space as tasks accumulate ("RGS becomes smaller"), threshold trades plasticity vs stability; in class-IL it does not work well (70.67 vs 81.80 for a replay method).

### 6b. Adam-NSCL (Wang et al.; arXiv 2103.07113, CVPR 2021)
Mechanism. Parameter update must lie in the null space of the uncentered feature covariance of all earlier inputs at each linear layer. After each task compute the covariance X_bar (running update with count n_bar), SVD, take the singular vectors of smallest singular values (range space U2) as approximate null space; project the Adam update: Delta w = U2 U2^T g (Eq. 6). Per-layer covariance of size h_l x h_l floats; each task has its own classifier. Rows (ResNet-18, task-IL, ACC / BWT): 10-split CIFAR-100 Adam-NSCL 73.77 / -1.6 (OWM 68.89 / -1.88); 20-split CIFAR-100 75.95 / -3.66 (OWM 68.47 / -3.37); 25-split TinyImageNet 58.28 / -6.05 (OWM 49.98 / -3.64, EWC 52.33 / -6.17, A-GEM 53.32 / -7.68, MEGA 57.12 / -5.90). Failure: needs a null space to exist (hence approximation controlled by a), cost of SVD per layer; no class-IL.

### 6c. OWM (Zeng et al.; arXiv 1810.01256)
Mechanism. Per layer maintain projector P_l, initial P_l(0) = I/beta. Weight update for task j >= 2: W_l := W_l + kappa P_l(j-1) Delta W_l^BP (task 1: no projection). After each task, update P_l recursively (RLS style, no matrix inverse) over the mean input of each batch x_bar: P_l(i) = P_l(i-1) - k_l x_bar^T P_l(i-1), k_l = P_l(i-1) x_bar / (alpha + x_bar^T P_l(i-1) x_bar). P_l is s x s floats per layer. Rows: shuffled MNIST 3 tasks 98.34 +- 0.02; 10 tasks 97.52 +- 0.03 ([784-800-800-10]); 100 tasks about 85.4 ([784-2000-2000-10]); disjoint MNIST 96.59 +- 0.06 ([784-800-800-10]) / 96.30 +- 0.03 ([784-800-10]) vs EWC 52.72, SGD 53.85, IMM 94.12 (which of 2-disjoint or 10-disjoint Table 2 reports, and whether single-head class-IL, is UNVERIFIED in the text); disjoint CIFAR-10 (5 groups of 2 classes, end-to-end 3 conv + FC) 52.83 vs EWC 31.09, IMM 32.36, MA 40.47. Contexts via a CDP module for CelebA. In Adam-NSCL's benchmarks OWM is 68.89 (10-split CIFAR-100) with BWT -1.88; in GPM's, 50.94 with BWT -0.30. Fit: dense, multiplicative, violates founder rule.

## 7. Synaptic metaplasticity in binarized networks (Laborieux et al., arXiv 2101.07592v1; Nature Communications version NOT read)
Only the 3-page arXiv summary was available (v2/v3 do not exist). Mechanism: BNN with real hidden weights W^h and binary weight W^b = sign(W^h), trained by backprop. Update: W^h := W^h - eta U_W f_meta(m, W^h) if U_W W^h > 0 (the update would shrink |W^h|), else W^h := W^h - eta U_W; f_meta(m, W^h) = 1 - tanh^2(m W^h). So the larger |W^h|, the harder to move toward zero and flip the sign (consolidation); growth is not impeded. Hyperparameter m = 1.35 for permuted MNIST (EWC lambda 5e-3 in their comparison). Interpretation: hidden weight magnitude tracks weight importance (loss increase when the binary weight flips correlates with |W^h|; Fig. 1b-c). No task boundaries needed. Protocols and reported results (text): permuted MNIST, up to 20 tasks, two hidden layers of varying width, "almost as well as EWC adapted to BNNs"; "stream learning" on Fashion-MNIST (2 x 1024 MLP) and CIFAR-10 (VGG-16) where the dataset is shown as sequential subsets with all classes in each subset, "closely matches" the full-dataset accuracy; numeric accuracy rows are not in the text (figures only), UNVERIFIED. No Split-MNIST/Split-CIFAR class-IL numbers: UNVERIFIED for the Nature Communications version, which is reported to include Split tasks but could not be read.
Storage: 1 bit per weight at inference; training keeps a float (or integer) hidden value per weight. Multiplies: backprop; but the consolidation factor is a function of an integer-quantisable |W^h| (lookup table or power-of-two schedule is DERIVED). Fit to our chip: the idea transfers to detector bit mask learning: an integer hidden counter per detector connection; sign flip changes the connection; consolidation = counter magnitude gates how easily it moves back toward 0.

## 8. Ranking for our design (binary, sparse, integer, no multiplies)

Evaluation criteria: no dense matrix, no multiply, integer/binary state, works without task id (class-IL), adapts the detector layer, numpy build time.

1. Recruitment of spare detectors with frozen old ones + FlyModel-style count update (FlyModel; DEN expansion rule; Ahmad boosting counters). Fully integer: a new class triggers assignment of spare detectors using novelty = low table margin; old detectors and old count rows never change, so old classes cannot be overwritten, only crowded (the sparse code makes crowding small; FlyModel's 0.64 vs 0.07 sparse-vs-dense ablation). Numpy in under a day: 2 to 4 hours for the FlyModel baseline (Theta binary random, top-l, add-only counters), plus about a day for the recruitment rule and tests. Risk: no paper reports exactly this; the new detectors' selection rule is ours (DERIVED).
2. Binary masks over detector-to-class connections with a margin-based task/class gate (SupSup-style supermask idea, XdG random gates, Piggyback/PackNet bit masks, HAT unit masks). 1 bit per connection (or per unit) per class group; selection is index lookup, no multiplies. Task inference by minimum entropy in SupSup needs gradients; replace by margin or count-table entropy over active detectors (DERIVED). Numpy in about a day (masks are given by a rule rather than trained). Limits: all of these papers are task-IL; class-IL needs the inference step to work with a single example; SupSup reports a single wrong inference yields 0 accuracy for the batch.
3. Integer metaplasticity (Laborieux) on the detector connections. Gives plasticity-stability inside one layer without task ids; needs a learning signal for detector bits (backprop in the paper), so we would have to substitute a local rule (Hebbian counter for co-active bits). Numpy 1 to 2 days, high risk of not working with a local rule (UNVERIFIED).
4. k-WTA with boosting (Ahmad): already the style of our detector layer; the integer duty-cycle counter is the ready recruiter of under-used detectors. Numpy under a day; it is a component, not a complete CL method.
5. Dual-memory consolidation (FearNet/CLS): fits conceptually (table = fast store, detectors = slow store, replay class mean binary codes); FearNet's implementation is a dense autoencoder. A binary version needs a generator of binary pseudo-samples (class mean code + noise) DERIVED. Numpy 2 days.
6. Progressive networks / L2G / DualNet: poor (quadratic growth, NAS, dense floats).
7. Gradient projection and null-space methods (GPM, Adam-NSCL, OWM): poor. Need SVD, covariance, P_l, float matrix-vector products; and the only class-IL rows are weak (GPM 70.67 on one-class-per-task digits vs 81.80 for generative replay; OWM disjoint CIFAR-10 52.83). Violates the founder's no-dense-matrix rule. Numpy in a day each, but as a GPU-side training experiment only, never on chip.

What can be built in numpy in one day (DERIVED, our estimate): FlyModel baseline; recruitment of spare detectors with freeze flags and margin-triggered assignment; random per-class-group unit gates (XdG-like); boosting counters; GPM or OWM as a float reference (dense, for comparison only, not for the chip).

Common failure modes across the set, from the papers: task id needed at test (HAT, Piggyback, PackNet, Adam-NSCL, GPM main results), mask capacity exhaustion with many tasks (PackNet, GPM), wrong routing in the inference step (FearNet BLA: Omega_new 0.824 vs oracle 0.912; SupSup single-image inference), reliance on a strong frozen pretrained backbone (Piggyback, FlyModel, FearNet), and class-IL being hard without replay (GPM's own statement).
