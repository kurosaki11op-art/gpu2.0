# Few-shot class-incremental learning: growing prototypes and forward compatibility

Read from arXiv PDF text (pdftotext) on 25 Oct 2026. Ids verified by the title and author header of each downloaded PDF: 2004.10956 (TOPIC, Tao et al., CVPR 2020), 2203.06953 (FACT, Zhou et al., CVPR 2022), 2104.03047 (CEC, Zhang et al., CVPR 2021), 1611.07725 (iCaRL, Rebuffi et al., 2017). Method sections, algorithm boxes, hyperparameters and the result tables were read in the text. Figure-only curves (for example FACT Fig. 5 and Fig. 7, TOPIC Fig. 5, CEC Fig. 5 and 6 cell values) were not turned into numbers: UNVERIFIED where noted. All accuracies below are numbers reported by the papers on image benchmarks (REPORTED, not measured by us). None of this is our measurement.

Protocol common to TOPIC, FACT, CEC: CIFAR-100 and miniImageNet use 60 base classes (500 images each) and 40 new classes in eight 5-way 5-shot sessions; CUB200 uses 100 base classes and ten 10-way 5-shot sessions. Accuracy is top-1 over all classes seen so far. PD = base-session accuracy minus last-session accuracy. The backbones are ResNet20 (CIFAR) and ResNet18 (the others): dense float CNNs, trained with backprop.

## 1. TOPIC (Tao et al., arXiv 2004.10956)

(a) Mechanism. The CNN is a feature extractor plus a classification head that gets |L(t)| new output neurons each session. Knowledge is held in a neural gas graph G = (V, E). Each node is a tuple (m, Lambda, z, c): centroid, diagonal variance, one pseudo image z (the base sample whose feature is nearest the centroid) and a class label c. Base training: 400 nodes learned by competitive Hebbian learning, Eq. 3 (every node moves toward the input by eta * exp(-rank/alpha); ranks come from sorting distances to all nodes) and Eq. 4 (edge between the best and second-best node set to age 1, other edges of the winner age by 1, removed above lifetime T). Per incremental session, k < K new nodes per new class (k = 1 for K = 5) are inserted and updated with the same rules. Two losses are added to cross-entropy (Eq. 7): anchor loss AL (Eq. 5) keeps the features of the old nodes' stored pseudo images near the stored centroids, weighted by the inverse variance (so high-variance dimensions move freely); min-max loss MML (Eq. 6) pulls a new sample toward the node of its own label and pushes that node away from neighbouring nodes of other labels beyond a margin xi, about the largest inter-node distance. Distillation loss is rejected on purpose. What is frozen: nothing is frozen, the CNN is fine-tuned for 100 epochs per session, only batchnorm statistics from the base set are fixed. What grows: the graph.

(b) Base set. 60 of 100 (CIFAR-100, miniImageNet) and 100 of 200 (CUB200). No small-base result.

(c) Results. Hyperparameters: eta 0.02, alpha 1, T 200, lambda1 0.5, lambda2 0.005, base lr 0.1 with 50 epochs, incremental lr 0.1 (0.01 CUB200), 10 seeds averaged. Final accuracy: CIFAR-100 24.17 (QuickNet) and 29.37 (ResNet18); miniImageNet 18.36 and 24.42; CUB200 26.28 (ResNet18). Ablation on miniImageNet ResNet18 (Table 3, last session): distillation only 18.69; AL only 21.80; AL without the variance weighting 21.36; AL + min term 24.18; AL + max term 23.80; AL + both (TOPIC) 24.42; AL + MML + distillation 23.49 (distillation hurts). Memory (Table 4, CIFAR-100 final accuracy): random exemplars 19.21/22.32/26.94/28.25/28.69/28.89 versus neural gas nodes 22.37/25.72/28.56/29.37/29.54/29.35 for 50/100/200/400/800/1600 memory units. So 50 nodes beat 50 exemplars by 3.2 points and the curve is flat above 400.

(d) Operations and memory. Inference: Euclidean distance to the nearest node in feature space (via a dense CNN); a distance-to-centroid search, no multiply is needed in principle after the features exist, but the features come from a float CNN. Training: backprop through the CNN with the two extra losses; per SGD step the graph update sorts all node distances. Memory: nodes (centroid + diagonal variance + one stored pseudo image + label) hence a few hundred feature vectors, claimed "negligibly small". Exact byte counts: UNVERIFIED (not stated in the text read).

(e) Limitations (our reading plus the paper): accuracy falls from 64.10 to 29.37 on CIFAR-100 (PD 34.73), far worse than the frozen-embedding methods below (CEC PD 23.93, FACT 22.50); fine-tuning the whole CNN on 25 images per session is what costs it; topology claims are only supported by confusion matrices, not a metric.

(f) Fit to L. The node = counting row analogy is direct: one neural gas node per class is a prototype with a count/variance, nodes are added on demand and old ones are anchored. What L can reuse: (1) growth rule: insert 1 node per new class, grow k nodes only if shots allow; (2) variance weighting: let a row's stability be inversely proportional to its spread (an integer count of how often each bit flipped); (3) the finding that distillation hurts and that a small number of well-placed nodes beats random exemplars. What does not fit: the competitive update with exp(-rank/alpha) and the CNN fine-tuning. Concrete small test: on the 6-of-10 split, compare 1, 2, 4 prototype rows per class (binary code, Hamming nearest) for base classes, and measure the old-class accuracy after adding a new class with 1 row versus 2; this mirrors Table 4 (nodes versus memory) at our scale.

## 2. FACT (Zhou et al., arXiv 2203.06953)

(a) Mechanism. Two stages. Base session: train embedding phi and a cosine classifier f(x) = (W/|W|)^T (phi(x)/|phi(x)|) where W holds one prototype per base class, plus V extra virtual prototypes P_v (V = number of new classes in total, default N*B, for example 40 on CIFAR-100). Loss (Eq. 5 to 7), four terms:
- L1 = cross-entropy over [W, P_v] with the true class as target.
- L2 = cross-entropy after masking out the true-class logit, target = the virtual prototype with the largest logit (pseudo label y-hat). This pushes every instance toward its nearest virtual prototype without lowering its own class score; the paper shows the gradient has no effect on the true class because the masked probability is 0.
- L3 = cross-entropy on a manifold-mixup instance z = g[lambda h(x_i) + (1 - lambda) h(x_j)] from two different classes, target = the virtual prototype with the largest logit. Mixing is done only between instances with the same index in a shuffled batch, so cost is O(n), not O(n^2).
- L4 = the symmetric masked term for z, target = the nearest known class. It prevents over-squeezing known classes.
Total loss L = Lv + Lf, trade-off gamma 0.01 on L2 and L4 (default). Lambda from Beta(0.5, 0.5) (alpha 0.5 default). Incremental sessions: embedding and old prototypes stay frozen; the new class prototype is the mean of its 5 shot embeddings (Eq. 4) and is appended to W. Inference with virtual prototypes (Eq. 8 to 11): p(y_i|phi(x)) = sum over p_v of p(w_i | p_v, phi(x)) p(p_v | phi(x)); with normalised vectors, Sigma = I and eta = 0.5 this is a mixture of exp(w_i^T(phi + p_v)) and exp(p_v^T(phi + w_i)) normalised over the known classes, weighted by a softmax over the virtual prototypes. With eta = 1 it collapses to ProtoNet (class-mean cosine) and the virtual prototypes are ignored. Frozen: whole embedding after the base session. Grows: rows in W only. Reserve: the V virtual rows, which stay in the model and are used at inference.

(b) Base set. 60 of 100 and 100 of 200 (plus ImageNet100: 60/40, and ImageNet1000: 600 base / 400 new in eight 50-way 5-shot sessions; accuracy curves there are figure-only, UNVERIFIED). No small-base result. The number of virtual classes sweep (V from 20 to 60 in 10 steps, gamma from 0 to 1) in Fig. 7b: "prefers small gamma and large V; trend trivial for V > 40" (cell values UNVERIFIED).

(c) Results (Table 1 CUB200, supplement Tables 1 and 2). Last-session top-1 and PD:
- CIFAR-100: FACT 52.10 (PD 22.50); CEC 49.14 (23.93); Decoupled-Cosine 47.68 (26.87); TOPIC 29.37 (34.73); Pre-Allocated RPC 5.14.
- miniImageNet: FACT 50.49 (PD 22.07); CEC 47.63; Decoupled-Cosine 45.63; TOPIC 24.42.
- CUB200: FACT 56.94 (PD 18.96); CEC 52.28; Decoupled-Cosine 49.31; TOPIC 26.26.
- Base-session accuracy is also higher for FACT on all sets (74.60, 72.56, 75.90).
Ablation (Fig. 5, CIFAR-100, curves only, no numbers in the text): L1 alone is the lowest; adding L2 (virtual prototypes, "growable") improves; adding L3 (mixed instances, "provident") improves again; L4 improves again; the full inference of Eq. 10 with eta 0.5 beats ProtoNet inference from the same trained model. The size of each step cannot be quoted (UNVERIFIED). Other reported effects: new-class accuracy is higher for FACT than CEC and Decoupled-Cosine (Fig. 7a, figure only); shots from 1 to 50 on miniImageNet, gain trivial above 20 shots; mixing method (manifold mixup, vanilla mixup, CutMix) barely matters (Fig. 7d). Reserve benefit measured as PD: FACT 18.96 against CEC 23.57 (CUB200), and the virtual-class variants are the only difference from the cosine decoupled baseline (26.21) besides the training schedule; this is a comparison across methods, not a clean A/B (CAUTION).

(d) Operations and memory. Training: ResNet18/20, batch 256, 600 epochs, SGD, lr 0.1 cosine decay, dense backprop. Inference: cosine similarity against all prototypes (|Y| + V) and, for Eq. 10, a softmax over V virtual prototypes: dense dot products and exponentials. Memory at deploy: (known classes + V) vectors of d dimensions (d = 512 for ResNet18, UNVERIFIED in the text read; d is not stated). Virtual rows are never trained again after the base session.

(e) Limitations (paper): assumes that few-shot new classes are the case; if new classes have plenty of data it becomes plain class-incremental learning and both forward and backward compatibility matter. Ours: V must be chosen in advance (equal to the number of future new classes); the result is robust only up to V near the true number; the virtual classes come from mixing two real base classes, so how well they match real unseen classes depends on the base set diversity (not tested with a small base); no ablation on the base set size.

(f) Fit to L. This is the most useful paper for us. In a counting-row machine, the virtual prototype = a spare count row with no real class label. FACT's trick is a training objective, not a runtime mechanism: during base training, every example is also asked to be nearer to one spare row than to all other known classes' rows (L2), and mixed-up examples are asked to land on spare rows (L3), with a balance term (L4) so that known classes do not get over-squeezed. For a binary gate network this suggests: (1) feature stage: train the gates with an auxiliary objective that keeps bit-space regions empty and compact, instead of letting the 6 base classes fill the code space; (2) pseudo-classes: build mixed examples by a bitwise mix (take a random half of the code bits from one example and half from another, from two different base classes) and count them into spare rows with a Hamming nearest-row assignment (a discrete analogue of manifold mixup); (3) inference: spare rows are kept and used as extra bases, or at least dropped before scoring.
Concrete small test (6 base classes, 4 held out): train the base binary gate network three ways: (A) 6 real rows only; (B) 6 real rows + 4 spare rows, spare rows trained only on bit-mixed pairs of different base classes (L3-like, no real labels); (C) B + the masked term L2 on real examples (each real example also pulled toward its nearest spare row). Freeze the gates, then add each held-out class by counting 5 shots into a fresh row (the spare row it is nearest to can be reused for it, which is a second variant) and report (i) base-class accuracy after adding 1, 2, 4 new classes, (ii) new-class accuracy, (iii) PD. FACT's own claim, that gains show up as lower PD and higher new-class accuracy, would be seen as B/C beating A on both. Seeds: at least 10 class-split permutations (which 6 classes are base matters on a 10-class set).

## 3. CEC (Zhang et al., arXiv 2104.03047)

(a) Mechanism. Three stages. (1) Feature pre-training on the base set, then the backbone is frozen. (2) Pseudo-incremental learning (Algorithm 1): sample a pseudo-base set (S_b, Q_b) and a pseudo-incremental set (S_i, Q_i) from base classes; rotate each pseudo-incremental class by a randomly chosen 90, 180 or 270 degrees so it behaves like a new class; build the base classifier W_b and incremental classifier W_i from the support sets (mean embeddings); concatenate and pass all class vectors through a graph attention network (GAT; nodes are class vectors, fully connected; attention e_jk = <phi(w_j), theta(w_k)>, softmax a_jk, update w_j' = w_j + sum_k a_jk U w_k); train the GAT with cross-entropy on the query sets of both parts; also fine-tune the last backbone layer with a small learning rate. GAT: 5000 iterations, lr 0.0002 halved every 1000 iterations. (3) Deployment: each new session's classifier is formed from the shot-mean embeddings (data initialisation, then trained with lr 0.1 for 100 epochs), concatenated with all earlier classifier rows, and the frozen GAT updates all rows. The GAT is permutation invariant and works for any number of rows, so it is reused at every session. Frozen: backbone and GAT. Grows: classifier rows.

(b) Base set. 60 of 100 and 100 of 200 (same as TOPIC). Pseudo-incremental episodes: best at way 15 and shot 1 on CUB200 (way 1 to 20 and shot 1 to 20 swept; Fig. 5 values UNVERIFIED). This is the only small-sub-base idea: the "base" in the episode is a random subset of the base classes; the paper does not test a total base set smaller than 60 classes.

(c) Results (Table 1 CUB200, last-session accuracy / PD): linear classifier 0.53 / 70.49 (finetuned, no decoupling), cosine 0.52 / 72.80; cosine decoupled 30.36 / 44.00; with data initialisation 49.31 / 26.21 (Decoupled-Cosine); with adaptation module trained by plain meta-learning 49.15 / 26.45 (no gain); full CEC (decoupled + data init + adaptation module + pseudo-incremental learning) 52.28 / 23.57. So the adaptation module trained correctly adds +2.97 points over the same classifier and removes 2.64 PD; without pseudo-incremental training it adds nothing. Rotation sweep: 180, 90, 270 degrees are best (average accuracy 61.33% on CUB200 with the three together, PD 23.57); small angles (5 to 20 degrees) make the fake classes too similar to the originals and help less. Final accuracy on all datasets: see table 0; CEC PD is 10.80 points lower than TOPIC on CIFAR-100, 12.52 lower on miniImageNet and 18.83 lower on CUB200 (their words, computed against TOPIC).

(d) Operations and memory. Dense CNN features; a mean embedding per class; one GAT pass over all class vectors per session (matrix products, softmax); parameters of the GAT and the layer sizes: UNVERIFIED (the supplement read contains only the result tables). Memory: one vector per class plus the small GAT.

(e) Limitations. A learned adaptation module needs backprop and dense attention; benefit is modest (3 points on CUB200); the pseudo-incremental trick only works when the fake new classes are made different enough (rotation) so that the module does not learn to ignore the context; no test with a small base set.

(f) Fit to L. The part worth taking is the idea of training on fake incremental episodes drawn from the base set, which is a cousin of FACT's virtual classes: both build fake unseen classes from base data (CEC by rotation, FACT by mixup). For a binary gate net, an episode would hold out 2 of the 6 base classes, count them from 5 shots into new rows, and check accuracy on the other 4 plus these 2 (a leave-two-out check). The GAT itself is not a fit (dense attention). A cheap non-matrix analogue is a count-based rule that nudges each class row away from nearby rows (a discrete margin update), tested in the same episodes. Concrete small test: use leave-two-out episodes only to choose a hyperparameter (for example the number of spare rows or how many bits to mix) instead of training a module.

## 4. iCaRL (Rebuffi et al., arXiv 1611.07725), baseline (optional)

(a) Mechanism. Class mean of stored exemplars: classify x by the nearest mean of phi(x) over each class's exemplar set (Algorithm 1). Exemplars are chosen by herding: greedily add the sample that keeps the running mean of the exemplar set closest to the true class mean (Algorithm 4); the set is an ordered list, so removal drops the last items (Algorithm 5). A fixed memory K is split evenly, m = K/t exemplars per class (Algorithm 2). The representation is updated by training on new data plus exemplars with a binary cross-entropy classification loss plus a distillation loss (outputs of the old network for old classes as targets). Nothing is frozen; the exemplar set shrinks as classes arrive.
Exact formulas (read in full). Network: feature map phi (L2-normalised, as are all means) followed by sigmoid outputs g_y(x) = 1/(1+exp(-a_y)), a_y = w_y^T phi(x) (Eq. 1). Classify: y* = argmin_y |phi(x) - mu_y| with mu_y the mean of phi over exemplar set P_y (Eq. 2), equal to argmax mu_y^T phi(x) for normalised vectors. Training loss (Algorithm 3): over the new data plus stored exemplars, sum of binary cross-entropy for new classes y = s..t (target = indicator of the label) and, for old classes y < s, a distillation term q_iy log g_y + (1 - q_iy) log(1 - g_y) with q_iy the old network's output stored before the update. Herding (Algorithm 4): for k = 1..m choose p_k = argmin_x | mu - (1/k)[phi(x) + sum_{j<k} phi(p_j)] |, so the list is prioritised and removal (Algorithm 5) just keeps the first m. Budget: m = K/t per class. Resource claim: memory = feature extractor + K exemplars + t weight vectors; if an upper bound on classes is known, weight vectors can be pre-allocated. Protocol: classes in fixed random order, 10 repeats with different orders on iCIFAR-100; iILSVRC reports top-5 accuracy; training: 70 epochs, lr 2.0 divided by 5 at epochs 49 and 63, batch 128, weight decay 1e-5 (CIFAR, 32-layer ResNet); 60 epochs, lr divided by 5 at 20/30/40/50 (ImageNet, ResNet18). The paper's own framing: two old strategies against forgetting are freeze-and-grow and rehearsal; iCaRL takes rehearsal. Headline curves (Fig. 2) are figures only; the iCIFAR-100 averages above are from Table 1.

(b) Base set. None: classes arrive in batches of 2, 5, 10, 20 or 50 (iCIFAR-100); batches of 10 (iILSVRC-small, 100 classes) or 100 (iILSVRC-full, 1000 classes). K = 2000 (CIFAR, 32-layer ResNet) and 20000 (ImageNet, 18-layer ResNet). Not a few-shot method.
(c) Results. Table 1a (average multi-class accuracy over steps, iCIFAR-100, batch size 2/5/10/20/50): iCaRL 57.0/61.2/64.1/67.2/68.6; LwF.MC 11.7/32.6/44.4/54.4/64.5; hybrid1 (network outputs for classification) 36.6/50.9/59.3/65.6/68.2; hybrid2 (no distillation) 57.6/57.9/59.9/63.2/65.3; hybrid3 (no distillation, no exemplar classification) 57.0/56.7/58.1/60.5/61.5. Table 1b: NCM classifier (class means recomputed after each update) 59.3/62.1/64.5/67.5/68.7. The same network trained with all data reaches 68.6% multi-class accuracy (stated in the Figure 2 caption). Memory sweep (Fig. 4): more exemplars help; from at least about 1000 prototypes iCaRL matches NCM and network outputs are not competitive.
(d) Operations and memory. Classification: distance to class means, no matrix; training: full backprop. Memory: K images plus the network.
(e) Limitations. Stores raw images (privacy, size), needs backprop with distillation, below joint training; the paper itself says this and notes that thousands of images fit in memory comparable to the network.
(f) Fit to L. The nearest-mean rule is the same as a counting-row prototype in Hamming space; the paper shows that it is robust to representation change, which is why TOPIC, CEC and FACT use it. For L the exemplar store corresponds to keeping the raw count rows only. Test: nearest-mean-of-codes as the base reference; it is the number any new idea must beat.

## 5. What to take away for L

1. All three few-shot papers end up with a prototype per class on a frozen or nearly frozen embedding, which is what a counting row is. Growth is by adding a row (TOPIC adds nodes, FACT and CEC add means). Our growth of nodes is therefore on the right track and should be judged against the PD column (22 to 35 on CIFAR-100).
2. Freezing the embedding after the base session is worth a lot: TOPIC (fine-tunes everything) loses 34.73 points on CIFAR-100, CEC 23.93, FACT 22.50. CEC's own ablation: decoupling alone cuts PD from 72.80 to 44.00 for the cosine classifier (CUB200).
3. Reserving room: FACT's gain over the decoupled cosine baseline is 4.4 points on CIFAR-100 (52.10 against 47.68), 4.9 on miniImageNet (50.49 against 45.63) and 7.6 on CUB200 (56.94 against 49.31) in last-session accuracy, a cross-method comparison, not an isolated ablation (the isolated ablation is figure-only, UNVERIFIED in size).
4. All numbers come from 60 or 100 base classes. Nothing here says how much a 6-class base can prepare; the diversity of the base set decides what the mixed-up pseudo-classes can imitate. This is the main gap and the thing our test must measure (UNVERIFIED for small bases).
5. Keep the matrix-free rule: TOPIC's competitive update, FACT's cosine/softmax inference and CEC's GAT all use dense float operations at train time or at inference. Only the ideas port (spare rows, mixed pseudo-classes, leave-two-out episodes, variance weighting), not the code.
