# Thinking research 3: "a guess about why" (hypothesis formation, testing and keeping)

Scope: how published work forms an explanation of a confusion ("class A and B differ because of this feature combination"), tests it on held data and keeps it only if it helps without hurting old knowledge. The aim is to learn from the papers and invent our own method, not to copy. All numbers in section (b) are AS REPORTED BY THE AUTHORS (not re-measured here). Everything in section (d) is a design with ESTIMATED costs and target criteria; nothing was run.

Rules respected (from `CLAUDE.md` and `PROJECT_MEMORY.md`): matrix-free (no dense matrix-vector products, no multipliers, no backprop in the chip); allowed are scans, counting tables, clauses (AND of literals), hash lookups, small state, local rules. Standing caution of 24 Oct 2026: no label at test time; labels may be used only in the learning phase, so a rule is tested either on a small labeled stored set (learning phase) or by label-free signals on the unlabeled probe.

Revision note (26 Oct 2026, second pass): the first version of this note was written from core-section reads. This version follows a full read of nine papers (see the table) and changes several conclusions; the changes are listed at the end of section (c).

## How the reading was done, and what was not obtained

- "Read fully" below means every page of the paper body and appendices was read, references skipped. For three of the papers (Popper, Tsetlin machine, SSDPS) the page-image reader returned no images (request limit), so I read the complete text layer of the PDF (all lines) instead; figures of those three were therefore not inspected, text, tables and equations were. For CEM, STOKE, MEND and the clause-size paper the page images were read as well as the text.
- "Core" means abstract, introduction, method and main results were read but not every page; these are marked "no".
- Not obtainable: CN2 (Clark and Niblett 1989), RIPPER (Cohen 1995), query-by-committee (Seung, Opper, Sompolinsky 1992) and the original abductive learning paper (NeurIPS 2019) are not on arXiv, and the hosts that carry them (the NeurIPS proceedings server and two university servers) returned HTTP 403 through the proxy, which I did not try to bypass. Substitutes used: the mechanism of AQ, CN2 and RIPPER as described in section 2 of Huynh, Fuernkranz and Beck (2023, Machine Learning, arXiv 2301.09936); the 2025 curriculum abductive learning paper for ABL; the Bayesian active learning paper for uncertainty sampling. These are secondary sources for the classics and I say so where it matters.
- No paper was found that analyses Tsetlin machine clauses specifically for class confusions. That gap is a finding.

## (b) Per paper

### 1. Popper (learning from failures) [read fully]
Mechanism: generate a hypothesis (a logic program) that satisfies a set of constraints; test it on positive and negative examples; if it fails, convert the failure into constraints. A hypothesis that entails a negative example is too general, so all its generalisations are pruned (Proposition 3); one that misses a positive example is too specific, so all its specialisations are pruned (Proposition 4); a hypothesis that entails no positive at all also triggers an "elimination" constraint that removes every separable program containing it. Subsumption is syntactic (clause C1 subsumes C2 if some substitution maps C1 into C2), hence cheap to check. Hypotheses are generated in order of increasing size, so the first solution is the smallest (Theorem 1). The constraint store is kept inside an answer-set solver that remembers learned conflicts between rounds.
Key numbers (reported): in the "buttons" task Popper learns a 10-literal solution within the one-minute limit while the generate-and-test baseline "Enumerate" (same system with only a "banish this one hypothesis" constraint) learns only 3 (p=20 buttons) or 1 literal (p=200); on the robot task Popper is on average about 40 times faster than Enumerate; list tasks: evens takes 4 s against 159 s for Enumerate, and Enumerate gets default accuracy 50% on most of the others. Learning time does not grow with the domain size, because the hypothesis space size depends on the declarations, not on the data (Proposition 1).
Limits stated by the authors: no noise handling (noisy examples would need relaxed pruning and keeping the best hypothesis so far, "likely to increase learning times"); the elimination constraint is NOT sound for all solutions, only for optimal separable definite programs (their Example 12 shows it prunes a complete hypothesis); proofs hold only when every hypothesis terminates and entailment is decidable; no predicate invention.
Transfers: (1) the two-sided failure logic maps to clauses: a clause is a set of literals, a specialisation is a superset of literals, so it fires on a subset of inputs; hence if a clause already breaks a protected example, every clause that contains it as a subset (a generalisation) breaks at least as many, and if it fixes nothing, every superset fixes nothing. This is exact for coverage counts. It is NOT exact for the decision, because our decision is a sum of votes against a margin; so pruning must be on counts of firings on protected or target examples, not on final accuracy. (2) A blacklist of failed literal sets stored as hashes, with a flag "too general" or "too specific". (3) Smallest first, so a short clause is tried before a long one. (4) Evidence that remembering failures matters: the only difference between Popper and Enumerate is the constraint store, and it changes what is learnable within the time limit. Does not transfer: ASP and Prolog machinery; exact all-positives, no-negatives acceptance (our data is noisy; Popper itself cannot handle that); anything that relies on logical entailment being monotone through a vote sum.

### 2. Tsetlin machine (original) [read fully]
Mechanism: a clause is the AND of the literals whose Tsetlin automaton (an integer state; include if in the upper half) is in the include half. In a multi-class machine each class has its own positive and negative clauses and the class with the largest vote sum is the output. Training one example (X, y): the class-y clauses get Type I feedback, and one other class q, chosen at random, gets Type II feedback (section 6.1: "a random class q != i is selected"). Type I (Table 2) pushes a firing clause to include literals that are 1 and pushes non-firing clauses to exclude, with probabilities (s-1)/s and 1/s; Type II (Table 3) acts only on a clause that fires wrongly and penalises the exclusion of a literal that is 0, which makes the clause stop firing ("introduce candidate literals that increase discrimination power"). Whether a clause is selected for feedback depends on the clipped vote sum v against the target T: probability (T - clip(v))/(2T), so feedback vanishes when the margin reaches T and the clauses are free to learn other sub-patterns. The frequency parameter s defines the sub-patterns the game targets: a sub-pattern is learned only if it covers at least about 1/s of its class (Definition 1, property 1).
Key numbers (reported): five benchmarks. Binary Iris 95.0 mean test (naive Bayes 91.6, logistic regression 92.6, MLP 93.8, SVM 93.6); Binary Digits 95.7 (SVM 50.5 because of overfitting); noisy XOR with 10 noise features and 40% label noise 99.3 (MLP 95.4, logistic regression 49.8); Axis and Allies 87.7 with 10,000 clauses and s = 40 (MLP 87.6); MNIST 98.2 (40,000 clauses, s = 10, T = 50, 400 epochs); the authors report the last epoch, not the best, "to avoid overfitting to the test set by handpicking". Test accuracy on MNIST kept rising while training accuracy approached 99.9%. The theory shows the Nash equilibria of the game are the optimal sub-pattern clauses for no noise or static noise, for a single clause and equal class sizes; extra noise is compensated by scaling s by a factor t in a derived range.
Transfers: this is our clause learner, and three details matter. (1) Type II is the only built-in "why not", and its partner class is random; there is no step that says "spend the Type II feedback on the Shirt versus T-shirt pair". A pair-targeted choice of q is a one-line change, and a counter of which literals Type II added per (clause class, partner class) is a free contrast table. (2) The summation target T makes feedback stop when the margin is large; in our terms, confusions are exactly the examples with margin below T, where the learner is still receiving feedback, so a confusion that persists after training means the clauses cannot express the separation at the current s and clause budget (not that feedback was withheld). (3) s is global; the authors note a possible follow-up with different s per clause. A Shirt style rarer than 1/s of its class will simply not be learned; a per-pair or per-clause s is a cheap knob for the confusion pair. Does not transfer: it has no accept or reject step, no held-out test, no notion of damage to old knowledge; every example updates; the theory covers a single clause, equal class sizes and symmetric noise.

### 3. SSDPS (statistically significant discriminative patterns) [read fully]
Mechanism: two-class data; for a pattern with counts a (class 1 with pattern), b (class 1 without), c (class 2 with), d (class 2 without), growth rate GR = (a/(a+b))/(c/(c+d)), odds ratio ORS = ad/(bc) and support difference SD are the discriminance scores, and a 95% confidence interval from the four counts (standard error sqrt(1/a - 1/(a+b) + 1/c - 1/(c+d)) on the log scale for GR, sqrt(1/a+1/b+1/c+1/d) for OR) gives a lower bound; a pattern is kept if its score is at least alpha and its lower bound at least beta. The search enumerates sets of transaction ids instead of item sets, with a closure operator, and Theorem 1 proves that adding negative transactions (making the pattern more general) lowers both the scores and the lower bounds, so the search can be cut when a node falls below the thresholds. Data is held as bit vectors (support by bit operations, AVX2).
Key numbers (reported): synthetic 100 transactions x 262 items: with ORS >= 2 alone 179,334 patterns in 38.69 s; adding a lower confidence bound >= 2 gives 18,273 patterns in 9.10 s; against CIMCP (5,403,688 patterns, 143 s) and SFP-Growth (out of memory after 172 s) SSDPS returns 49,807 patterns in 73.69 s (not a like-for-like comparison, as the authors say). On genetic data (96 cases, 50 controls, 103,611 variants) it finds patterns containing the two known risk variants for every setting tried, after a heuristic pre-filter whose thresholds the authors call hard to choose.
Correction to my first note: the authors' worked example (GR 2.4 with a 95% interval of 0.37 to 16.6) is described in the paper as significant because the score lies between the bounds, which is true of any score; the real evidence for the interval as a filter is the drop from 179,334 to 18,273 patterns in the synthetic experiment. The authors list multiple-testing correction as future work; the interval is per pattern and ignores how many patterns were tried.
Transfers: the test is four counts, one log and one compare, so it is matrix-free and cheap, and it is a reasonable guard on a proposed clause with little data. The bit-vector representation of transaction sets is our code layout. The anti-monotone cut (a more general clause cannot have a better lower bound) is the same pruning logic as Popper's. Does not transfer: exhaustive tidset enumeration (too large for 4,608 bits); the interval gives no protection against the number of candidates we try (we must add that), and with few items in class 2 the lower bound is very wide, which is a feature (it stops us trusting a small sample).

### 4. CEM (pertinent positives and negatives) [read fully]
Mechanism: for an input classified as t0, a pertinent negative (PN) is the minimal set of absent features whose addition makes the model predict another class; a pertinent positive (PP) is the minimal set of present features that alone keeps class t0. Both solve min c*f(x0,delta) + beta*|delta|_1 + |delta|_2^2 + gamma*|x0+delta - AE(x0+delta)|_2^2 with a hinge loss f on the margin between the top class and the rest; solved by projected FISTA, 1,000 iterations, c searched over 9 values; the autoencoder term keeps the explanation near the data manifold and is dropped when data is too scarce. The paper stresses that PNs matter most "when inputs in different classes are close to each other" and could be used for "model debugging, finding biases in the model in terms of the type of errors it makes".
Key numbers (reported): MNIST CNN 99.4% test accuracy, explanations judged by eye (no number); procurement-fraud network (10-fold accuracy 91.6%): experts accepted the explanation for 90.3% of 45 invoices (PP) and 94.7% (PN); LIME 86.6%, LRP 88.2% for PP only; fMRI classifier (61.17% accuracy) with a plausible network-level explanation; on all three data sets 100% of the PNs changed the predicted class and 100% of PPs kept it (this is by construction, since the optimiser stops when the hinge is zero).
Transfers: for binary codes and a table-sum classifier the optimisation is unnecessary. Our score for class k is a sum of counter values over the set bits, so flipping bit b changes the score gap between predicted class A and runner-up B by a known table lookup (sum of counters minus counters); a greedy pick of the bits with the largest gap change, until the gap changes sign, is the exact pertinent negative of that example under the current table, with an L1-like sparsity (count of flips). The paper's own observation that PNs are informative only for close classes is our situation (Shirt against T-shirt, Pullover, Coat). Does not transfer: the optimiser, the autoencoder; the paper explains the model, not the world, so a flip-set only becomes a hypothesis about garments after a held-out test; the 100% figures are tautological and must not be used as evidence of explanation quality.

### 5. STOKE (stochastic superoptimisation) [read fully]
Mechanism: Markov chain Monte Carlo over loop-free programs of length 50. Moves: change an opcode, change an operand, swap two instructions, replace an instruction (probabilities 0.16, 0.5, 0.16, 0.16, plus an "unused" token move, 0.16). The cost is correctness (the Hamming distance, summed over live registers, between the rewrite's outputs and the target's on a set of test cases, with weights for faults) plus a performance term; a proposal is accepted with probability min(1, exp(-beta * c_new / c_old)) (the ratio of new to old cost), beta = 0.1; a cheaper proposal is always accepted. Four ideas matter here. (a) Test cases first, symbolic validation second: about 500,000 test-case runs per second against under 100 validations per second; a failed validation returns a counterexample that is added to the test set. By default 32 test cases. (b) Graded cost: the "improved equality metric" gives almost zero cost to a rewrite that computes the right value in the wrong register; the strict version made the search no better than random in 1,000 s, the improved one converged in about 700 s (Figure 7). (c) Two phases: a synthesis phase that ignores speed and an optimisation phase that starts from a known-correct program, because the expert solution is reachable from random programs only through a very low-probability path. (d) Early abort: draw the random number first, compute the largest cost that would still be accepted, and stop running test cases as soon as the running cost exceeds it; this raised proposals per second almost threefold (Figure 5).
Key numbers (reported): matches or beats gcc -O3 and icc -O3 on 25 Hacker's Delight kernels plus Montgomery multiplication, linked list and saxpy; up to about 6.6 times faster than -O0 on one benchmark; 40 cores, 30 minutes budget. Failures (stated): three kernels (round up to power of two, next highest with same number of one-bits, exchanging two fields) are not synthesised because a wrong program differs from the right one in a single bit and the cost gives no partial signal; for those only the optimisation phase from the original program worked. It also cannot handle loops.
Transfers: this is the closest published template of our loop. (1) A cheap test set with graded cost, an expensive confirmation, and counterexamples appended to the test set. (2) Early-abort acceptance: in hardware the LFSR draw comes first and the AND-popcount scan over the protected set stops as soon as the damage budget is exceeded, so most rejected proposals cost a few words of work. (3) Start from the known-correct state (the current table) and only propose local edits ("optimisation phase"); never rebuild. (4) Warning: where a wrong guess differs from a right one by a single bit with no partial credit, local search fails; for our clauses, a margin-based cost (how much the Shirt-versus-X gap moved) supplies the partial credit that 0/1 flips lack. Does not transfer: exp(), exactness of the validator (we have only samples), program length.

### 6. MEND (model editing) [read fully]
Mechanism: an edit changes a trained model's answer on one input x_e to y_e. MEND trains small networks that map the fine-tuning gradient (a rank-1 outer product per layer) to a weight update. For our purposes the evaluation protocol is the finding: edit success (ES) is accuracy on the edited input and on its equivalence neighbourhood (paraphrases); locality is measured as drawdown (DD) on unrelated inputs (accuracy loss or perplexity increase), and as a KL divergence in training; fine-tuning on the single edit overfits, harming both locality and generality, even with a KL term.
Key numbers (reported): Table 3 (very large models): fine-tuning ES 0.55 to 0.87, MEND 0.81 to 0.89 with low drawdown; a learned knowledge editor (KE) fails at that scale (ES 0.00 to 0.04). Table 5 (stacked edits, BART-base on zsRE): 1 edit ES 0.99 versus 0.98 (ENN versus MEND); 25 simultaneous edits 0.35 versus 0.89; 75 edits 0.16 versus 0.78; 125 edits 0.11 versus 0.67 with drawdown about 0.01. Appendix G, "editing through caching": store the hidden state and answer of each edit and output the stored answer when a new input's state lies within a distance epsilon of a stored one. With the best epsilon it matches MEND on short inputs (FEVER ES 0.96 vs MEND above 0.99; zsRE above 0.99 vs 0.98, drawdown 0.002 vs 0.002) but fails on harder inputs (zsRE-hard 0.32 vs 0.66; Wikitext 0.001 vs 0.86) and is very sensitive to epsilon: half the best value gives ES 0.70, twice the value gives drawdown 0.25 and 0.22. Listed failure modes: overgeneralisation (the edit leaks to a related but different input, for example "Back in Black" answered "Michael Jackson") and undergeneralisation. Locality inputs "are not challenging enough to prevent over-generalisation" (stated limitation).
Transfers: (1) the three-part test: reliability on the cases the rule was made for, generality on held-out similar cases, locality on unrelated cases, all as separate counts. (2) Multiple simultaneous edits interact; test the bundle, not only the single rule (ES fell from 0.99 to 0.11 for the weak editor at 125 edits). (3) The caching baseline is a matrix-free exception memory: store the code of each hard confusion plus its corrected class and answer by nearest stored code within a Hamming radius. The paper shows exactly where this works (simple, short inputs, similar inputs) and where it collapses (complex inputs, wrong radius). That is evidence for, and a warning against, an exception-table design (Design D below). Does not transfer: gradient-to-update networks and rank-1 weight edits.

### 7. Clause size constrained Tsetlin machine [read fully]
Mechanism: once a clause has more included literals than a budget b, the Type I columns that reward inclusion are switched off, so only Exclude is reinforced and oversized clauses appear only briefly. Type II is unchanged and can still push a clause over budget, after which Type I pulls it back.
Key numbers (reported): MNIST with 8,000 clauses per class: at most 8 literals gives 98.40 (average 5.8 literals) against 98.32 unconstrained (47.7); BBC Sports at most 8 gives 99.1 against 94.14 without budget; CIFAR-2 with a budget of 1 collapses (69.82) while 8 gives 91.21; with only 250 clauses a budget of 1 gives 88.20 and a budget of 4 gives 95.96. When the budget is too tight the clauses keep exploring (the average number of literals rises to 30.8 on CIFAR-2 with budget 1). A human check of unsupervised clusters (Table 5): 85-89% of the supporting (positive-polarity) clauses were judged recognisable but only 32-39% of the discriminating (negative-polarity) clauses.
Transfers: short rules are the ones a small held-out set can test; a budget of 4 to 8 literals costs nothing in accuracy in this paper. Important for us: discriminating clauses, the ones that carry the "why not", were the hard ones for people to read, so do not expect the contrast rules to be self-explanatory; they must be judged by counts. Too tight a budget on weak (pixel-level) literals makes learning fail, so budget by evidence not by a fixed small number. Does not transfer: nothing, except that it analyses no confusions.

### 8. Invariant risk minimisation [read fully]
Mechanism: with data from several environments, find a representation on which one classifier is optimal in every environment; the practical penalty is the squared gradient of each environment's risk with respect to a fixed scalar classifier. It is stated together with causal reasoning (invariant predictors use the direct causes of the label).
Key numbers (reported): Colored MNIST: ERM 87.4 train, 17.1 test; IRM 70.8 and 66.9; optimal invariant model 75 and 75; grayscale-oracle 73.5 and 73.0. On synthetic tasks IRM beats ICP (invariant causal prediction), which is "conservative", rejecting most covariates and giving large errors on the causal weights. Theory: with a rank-r representation the guarantee needs at least d - r + d/r environments in linear general position, which the authors call pessimistic; in practice two environments often suffice.
Cautions that change my first note: the authors say that extracting random subsets of one data set does not make diverse environments, and that splitting a data set by conditioning on arbitrary variables "can generate diverse environments, but may introduce spurious correlations and destroy the invariance of interest". So environments must reflect a real change in how the data is produced. Invariance also costs fit: IRM's train accuracy is 70.8 against 87.4 for ERM. The regulariser strength is chosen on a held-out environment.
Transfers: the principle as a min-over-environments test with counts: keep a literal or clause only if its contrast has the same sign, with a lower bound above zero, in each environment. Candidate environments for us that reflect a real change of source: stream stage (the continual stages), real stored images versus images generated from the dreams, original versus a distortion (small shift or added noise) of the same images. Splitting by brightness or by a feature of the image itself (my first suggestion) is the kind of split the authors warn about, so it is dropped. Does not transfer: the gradient penalty; a causal reading (pixels are not causal variables, as the authors themselves note); with few confusions per environment the test will be conservative, as ICP was.

### 9. Contrast pattern mining survey [read fully]
Content: contrast patterns (emerging patterns, jumping emerging patterns, contrast sets, subgroups) are itemsets whose support differs strongly between classes. Definitions: EP if growth rate >= rho; JEP if support is zero in one class; minimal and maximal EPs; JEPN, jumping emerging patterns with negated items (so literal and its negation are both allowed, as in clauses); noise-tolerant EP (NEP) with two thresholds; Chi-EP with a chi-square test; BEP for imbalanced classes. Measures listed with formulas: growth rate, support difference, WRAcc, odds ratio, gain, SupMaxK (support minus the largest support of any sub-pattern in the other class), mutual information, chi-squared, p-value. Strategies: threshold-based versus top-k; algorithm families: border-based (MBD-LLBORDER, JEPProducer, DeEPs, a lazy instance-based classifier), tree-based (CP-tree and others), evolutionary fuzzy, decision-tree-based (induced forests), ZBDD.
Key numbers: none comparable (a survey). Open problems stated: redundancy of the pattern set is "not yet solved"; no open-source platform; class imbalance; mining multivariate patterns is harder to understand.
Transfers: a vocabulary and a menu of scores computable from four counts: use support difference and SupMaxK rather than growth rate when the other class count is near zero (growth rate is infinite or unstable), and use NEP-style two thresholds (rare in the partner class, frequent in the target) because pixel data is noisy. JEPN confirms that negated literals belong in a contrast pattern. DeEPs is an instance-based variant that mines patterns only for the test instance: for us, "which contrast bits does this doubtful image have" is the lazy analogue. Does not transfer: complete border mining; none of the surveyed methods says how to test a mined pattern on held data or to protect old knowledge.

### 10. LORD and the AQ / CN2 / RIPPER lineage [partly read; the classics are second-hand]
Mechanism as described by the authors for the family: separate-and-conquer. AQ picks an uncovered example, searches the best rule that covers it and removes covered examples; CN2 drops the seed example and searches the best rule over all examples and classes, with statistical significance and the m-estimate; RIPPER adds incremental reduced-error pruning (simplify a rule on a separate pruning set) and a post-processing loop that asks whether replacing one rule of the set by a regrown and pruned one lowers the error of the whole rule set. LORD instead finds, by a greedy grow phase and a prune phase, the best rule for every training example using counts held in prefix trees, then filters; its variant LORD* learns a new rule only when the example is misclassified by the current set, and keeps it only if it beats the rule currently used. Rule heuristic: the m-estimate h = (p + m*P/(P+N)) / (p + n + m) with m = 0.1, a purely count-based formula. About 5.4% of the examples needed more than one grow-prune round.
Transfers: the m-estimate is a count-only score that discounts rules with few covered examples; RIPPER's "replace one rule if the whole set does better on a pruning set" is a propose-test-keep step with a separate set; LORD*'s "learn only on failure, keep only if better than the incumbent" is the closest published match to a learning-from-failure loop on counts. The authors also note that rules found later in a covering run rest on shrunken data ("insufficient statistic information"), a reason to test each candidate on the same held set rather than on what remains. Does not transfer: prefix-tree machinery; those papers have no old-knowledge guard because they are batch learners.

### 11 to 17. Core-read papers (shorter notes)
- CORELS (11): branch and bound over rule lists with a hierarchical objective (error plus length penalty); a lower bound on a prefix holds for all its extensions; minimum support and minimum correct count per rule; identical features with opposite labels give an unavoidable error bound. Reported: optimal list in seconds, optimality certified in about 10 minutes; accuracy at least similar to CART and C4.5. Transfers: the unavoidable-error count (identical hashed codes with opposite labels among Shirt and T-shirt) as a ceiling on any rule's gain; the minimum-support filter. Does not transfer: exhaustive search over a 4,608-bit code.
- DreamCoder (12): wake (search programs for tasks), sleep abstraction (turn repeated fragments into library entries, with a description-length prior), sleep dreaming (train the search guide on replays and fantasies). Reported: about 20 list operations from 109 tasks; a sort in under 10 minutes with 5 library calls against 32 calls and an estimated 10^72 years by brute force. Transfers: keep a rule only if it explains several confusions (reuse test); test on dreams. Does not transfer: network guide, Bayesian marginalisation.
- Bayesian active learning (13): acquisition by entropy, BALD, variation ratios, mean standard deviation, from dropout samples. Reported: 5% MNIST error with 295 labels versus 835 for random; 1.64% with 1,000. Transfers: query by margin and by disagreement of two cheap views (fast table versus slow table); warns that uncertainty can chase noise. Does not transfer: Bayesian CNN.
- Curiosity module (14) and random network distillation (15): intrinsic reward from prediction error; the first uses features trained to predict the agent's own action so that uncontrollable noise is ignored, the second uses a fixed random target to avoid the noisy-TV trap. Reported: RND finds more than half the rooms in Montezuma's Revenge without demonstrations. Transfers: a count-based novelty (visits to a hashed code bucket) is deterministic, so it cannot be fooled by noise; surprise should be measured in features relevant to the decision. Does not transfer: networks, policy gradient.
- Curriculum abductive learning (16): abduction proposes label sets consistent with a knowledge base, consistency optimisation picks one, the model is retrained; a large knowledge base makes the candidate space explode, so the knowledge base is split into sub-bases introduced in phases when each label's accuracy passes a threshold; reported better accuracy, speed and stability on addition with images and a chess task. Transfers: the control idea (simple hypotheses first, advance only when earlier ones pass). Does not transfer: it needs a symbolic knowledge base that we do not have; our only background knowledge is counts.
- Counterfactual explanations (17): closest point that changes the output, with L1 distance weighted by the inverse median absolute deviation to get few changed features; return several. Transfers: the same sparse flip-set as CEM. Does not transfer: gradient search; legal part.

## (c) Synthesis

### The generic loop in the literature
1. Propose from a structured space: a program (Popper), a one-instruction mutation (STOKE), the literal that Type II adds (Tsetlin machine), the smallest change that flips the output (CEM, counterfactuals), the pattern with the largest growth rate (contrast mining), a grown-and-pruned rule (RIPPER, LORD).
2. Test cheaply on a stored set, with a graded score where possible (STOKE's partial-credit cost, CEM's margin hinge, RIPPER's pruning set).
3. Constrain: let the failure remove many candidates (Popper's generalisation and specialisation pruning, SSDPS's anti-monotone cut, CORELS's prefix bound, STOKE's counterexample).
4. Confirm with an independent or more expensive check (STOKE's validator, CORELS's certificate, MEND's locality and generality sets, IRM's held-out environment).
5. Keep with a record and prefer the short one (library growth in DreamCoder, clause budget in the Tsetlin variant, optimal size in Popper, length penalty in CORELS).

### What makes the test trustworthy with little data
- Confidence bounds on counts, not point scores (SSDPS), with the explicit caveat that the number of candidates tried is not charged (the authors list this as future work). For us: each candidate tested spends part of an error budget; stricter bound as the count of tests grows.
- Separate sets for proposing, testing and confirming. Evidence: Tsetlin machine authors report last-epoch accuracy rather than the best to avoid picking the test set; RIPPER prunes on a held-out pruning set; STOKE feeds validation failures back. None of the papers has a formal charge for reusing one small test set many times.
- Short rules (clause budget; CORELS; Popper's smallest first). The clause-size paper shows no loss from 4 to 8 literals on its tasks.
- Evidence across environments that differ by how the data was produced (IRM), with the warning that arbitrary splits can destroy the invariance and that the method is conservative.
- A null or reference set: dreams, unrelated unlabeled probe images (MEND's drawdown, locality).
- A ceiling (CORELS): identical codes with opposite labels bound the possible gain.
- Partial credit in the cost (STOKE's improved equality metric): without it a one-bit-wrong candidate looks no better than random.

### How acceptance is guarded
Against overfitting: a lower bound, a complexity budget and a separate confirmation set. Against hurting old knowledge: MEND's drawdown on unrelated inputs and its warning that stacked edits interact (ES 0.99 to 0.11 over 125 edits for the weak editor), plus rehearsal of stored old items and an explicit cumulative budget. No paper gives a ready damage budget for a counting-table classifier; our existing counted veto bound is the nearest piece. Reversibility: STOKE can walk back; a ledger with the previous value per edit gives us the same cheaply.

### What the literature does not give us
- No source analyses Tsetlin clauses for confusions; Type II feedback is the only built-in discrimination and its partner class is random.
- All guarantees (Popper, CORELS, STOKE's validator) assume noise-free labels or exact checks; our pixel data is noisy and the Shirt/T-shirt confusion may be partly irreducible (project note: Shirt recall 63-74% picture-only; CNN ruler 79.4%), so expect a small ceiling.
- Active learning and curiosity pick what to ask, contrast mining and pertinent negatives say what differs, but none connects the two with an accept-or-reject test on old knowledge. That joint is ours.

### What changed after the full reads (compared with the first version of this note)
1. SSDPS: the interval is a useful filter (179,334 to 18,273 patterns on the synthetic set) but the paper's own worked example does not show that; and no multiple-testing charge exists in the paper.
2. Popper: pruning is sound only for monotone coverage, so for our vote-sum classifiers it must be done on firing counts, not decisions; the elimination constraint is unsound outside optimal separable programs; no noise handling.
3. Tsetlin machine: Type II partner class is random in the original multi-class design, so a pair-targeted partner is a concrete small lever; s sets a minimum sub-pattern frequency (1/s), a hypothesis for why rare Shirt styles are missed.
4. MEND: the caching baseline in its appendix is the closest published relative of an exception table and shows its failure on complex inputs and sensitivity to the radius; this adds Design D.
5. IRM: arbitrary environment splits (my brightness quartiles) are explicitly warned against; replaced by stream stage, real versus dreamed, original versus distorted.
6. STOKE: early-abort acceptance (draw the random number first, stop testing when the allowed cost is exceeded) and the synthesis-versus-optimisation split are added; cost must give partial credit.
7. Clause-size paper: discriminating clauses were far less recognisable to people (32-39%) than supporting ones (85-89%), so contrast rules need count-based judgement, not human reading; a budget that is too tight on weak literals makes learning fail.
8. CN2/RIPPER/QBC/original ABL: unreachable (HTTP 403 through the proxy); the first two are covered second-hand through LORD's description, the last two not at all.

## (d) Our own method sketch

Common setting: Fashion-MNIST with the current L code (4,608-bit codes), the clause banks and counting tables as shipped. Target pair: Shirt (S) against T-shirt/top, Pullover, Coat (T3). Baseline Shirt recall 0.5-0.67, L alone 0.638 (project figures). Primitives only: per-class bit frequencies and counts, popcount of ANDs, small counters, an LFSR, a stored rehearsal set (about 20 images per class), unlabeled probe images. Costs are ESTIMATED from operation counts; a code is 4,608 bits = 72 words of 64 bits.

Shared bookkeeping, the rule ledger: for each kept rule store the literal set (up to b = 4 literal indices), type (boost S or veto a T3 class), the class pair, the counts at acceptance (fixes, breaks, probe flips), the result per environment and an undo record (previous values). About 64 rules x 16 bytes = 1 KB. A second table, the failure blacklist, holds a 32-bit hash of each rejected literal set with the flag too-general or too-specific (Popper's idea, applied to firing counts only).

Acceptance guard used by all designs (the damage budget): a rule is kept only if (i) the lower confidence bound on fixes/(fixes+breaks) on the test set clears a threshold, (ii) breaks on stored images of every other class are at most k_old, (iii) the share of unlabeled probe images whose top class changes is at most B_flip, (iv) it covers at least m confusions (reuse), (v) its literal count is at most b, and (vi) the cumulative rehearsal damage since the start is under the total budget. The error budget for (i) tightens with the number of candidates tested so far (our addition; the papers do not provide it).

### Design A: contrast counters propose, count-based failure constraints and a lower-bound test keep
Candidate generation (all counting): for training examples of true class S with doubt toward a T3 class X, count per literal (bit or its negation) the confusion examples that have it, n_conf[S,X][literal], and from correctly decided X examples n_ref[X][literal]. Score each literal by support difference and by SupMaxK-style margin, and by the lower confidence bound of the odds ratio from the four counts; keep the top 16. Candidate clauses: greedily AND 2 to 4 of them, each time adding the literal that most increases covered S confusions minus covered X-correct examples (the m-estimate with m = 0.1 can be used as the tie-breaker). Boost S or veto X.
Test on a separate set B (confusions not used for proposing, plus the stored rehearsal images of all ten classes) with the shared guard. Failure handling as in Popper but on counts: a candidate that breaks protected examples gets a literal added (specialise), and its literal set and all generalisations are blacklisted as too-general; a candidate with no fixes gets a literal dropped and is blacklisted as too-specific. A candidate needs to differ from a blacklisted set by inclusion test only (bit mask). Stop after K = 200 candidates, or 3 rounds with no acceptance.
Minimal experiment: train L as now; hold out 25% of the training Shirt/T3 confusions as set B; run; evaluate on the 10,000 test images. Controls: no rules; the same number of random 3-literal clauses through the same guard (does the contrast proposal matter?); the project's current counted veto rules.
Success criterion: Shirt recall +3 points (0.638 to at least 0.67) on the test set, overall accuracy lower by no more than 0.2 point, no class recall lower by more than 0.5 point, and the random-clause control gains at most 0.5 point.
Expected cost (ESTIMATED): proposing under 10^6 counter operations plus a sort of 4,608 entries per round; testing 400 stored images x 72 words = 29k word operations per candidate, 200 candidates = 6 million; ledger and blacklist about 2 KB. Seconds on a CPU. Uncertainty: the project's earlier finding that counted vetoes are bounded but weak suggests +1 to +2 points, below the target; a null result (accepted rules exist but gain under 1 point) would suggest the missing evidence is not in the 4,608-bit code.

### Design B: pair-targeted Type II counters and a pertinent-negative flip-set explainer, with an invariance test
Two parts. B1 (cheap, change of training): in the clause learner, when a Shirt example is trained, choose the Type II partner class q as the runner-up (the doubt partner) instead of a random class (the original multi-class design draws q at random), and count per (clause class, partner class) which literals Type II adds; also try a per-pair s (finer s for the S versus T3 clauses, because s sets the minimum sub-pattern frequency 1/s). B2 (explanation): for each confused example compute the pertinent negative by the table-lookup greedy: sort bits by how much flipping them changes the S-versus-X score gap, flip the smallest prefix that makes S win (at most 8 bits), and count how often each (bit, direction) appears over all confused examples; the 3 to 4 most frequent form a candidate clause for Design A's test.
Invariance test (replacing my first brightness idea): environments are stream stage 1 versus stage 2, real stored images versus images dreamed from the class counts, and original versus a small shifted or noisy copy of the same image. Keep a literal only if its contrast sign agrees and its lower bound is above zero in every environment. Control: inject 20 spurious literals (a bit forced equal to the label in the proposing set, independent in the test set) among 100 candidates.
Minimal experiment: (i) injection test; (ii) B1 alone: retrain with partner-targeted Type II and compare Shirt recall and per-class recall with random partner (same seeds); (iii) B2 clauses through Design A's guard with and without the invariance filter.
Success criterion: the filter rejects at least 90% of spurious literals while keeping at least 70% of the real candidates; B1 alone improves Shirt recall by at least 1.5 points with total accuracy not lower by more than 0.2; the filtered pipeline gains at least as much as the unfiltered with at most half the probe flip rate.
Expected cost (ESTIMATED): B1 changes one random draw and adds a counter table of (classes x classes x literals) small counters (about 10 x 10 x 4,608 x 1 byte = 460 KB of statistics in simulation, or only for the S pair: 4.6 KB); B2 one pass over the confused examples with a table lookup per bit, under 10^7 operations; invariance counters 3 x 4,608 x 2 bytes = 28 KB. Uncertainty: with a few hundred confusions per environment the lower bounds will be wide and the filter may reject everything (IRM and ICP were conservative in the same way); the injection test measures the sample size needed. B1 is the most likely to give a real gain at low risk, and also the most likely to be unrelated to "explanation".

### Design C: local hill climbing on the clause banks with early-abort acceptance, a damage budget and an undo log (STOKE-like)
Candidate generation: a mutation changes one include state (nudge one automaton state by one step) in a Shirt or T3 clause that fired on a confusion; 70% of proposals take literals from Design A/B's contrast lists, 30% random literals (STOKE's local and global mix). Start from the shipped state and only edit it (optimisation phase only; never retrain).
Cost: C = (sum over confusions of the hinge on the S-versus-X score gap, so partial credit exists) + lambda1 x (errors on stored images of other classes) + lambda2 x (probe flip rate) + lambda3 x (literal count). All weights powers of two (shifts, no multiplies). Accept if C does not rise, or with probability 1/8 if it rises by at most 2 units, decided by an LFSR compare; the LFSR value is drawn first, the largest allowed cost is derived, and the scan over the stored images aborts as soon as that cost is exceeded (the STOKE early-abort trick), so most rejections cost a few words.
Guards: three rotating sets (propose, test, confirm). Every 20 accepted edits run the confirm pass and roll back the last 20 edits if the confirm score fell. A cumulative damage counter stops the loop at the budget (for example 0.3 point of total rehearsal accuracy). Undo ring of 256 x 4 bytes (clause id, literal id, old state) = 1 KB. Failed confusions are added to the test set (counterexamples). What to ask next: choose confusions by lowest top-2 margin plus a hash-count novelty bonus (visits to the code bucket), so the loop does not keep asking about irreducible pairs; labels are requested only in the learning phase.
Minimal experiment: 2,000 mutations on the S/T3 banks, three seeds, with Design A's controls and a control that replaces the biased proposals by random ones. Record accepted share, rollbacks, cumulative damage, test-set versus confirm-set gain.
Success criterion: Shirt recall at least 0.67 on the test set in 2 of 3 seeds; rehearsal accuracy loss at most 0.3 point; the biased proposals reach the target in fewer mutations than the random ones; and the gap between test-set and confirm-set improvement stays under 1 point.
Expected cost (ESTIMATED): each proposal re-evaluates only the changed clause on about 400 stored items = 29k word operations at most, far less with early abort; 2,000 proposals = 58 million operations at most. Hardware: one AND-popcount unit (already there), an LFSR, a 1 KB undo ring, a few counters. Uncertainty: with only a few hundred test items the climb will fit the test set; the rotation of three sets must work; the first measurement is the test-versus-confirm gap. If the gap exceeds 1 point the loop is fitting noise and the bound must be tightened.

### Design D: exception table (hypothesis kept as stored cases, not as a clause)
Motivated by MEND's caching baseline. Keep a small table of confusion exceptions: the code of an image that the main model gets wrong (and its true class, given in the learning phase). At inference, if the nearest stored exception is within a Hamming radius r, boost its class. The radius is the dangerous knob in the paper (half the best radius: ES 0.70; twice: drawdown 0.25), so choose r on the confirm set by the same guard (breaks on other classes at most k_old, probe flip rate at most B_flip), per exception, not globally: each exception stores the largest radius at which it did no harm on the protected set (a per-item safe radius, measured by a scan). This gives a rule that is as local as its evidence and can be removed by deleting a row.
Minimal experiment: store up to 64 exceptions of S misclassified as T3 in the training pass; compute per-item safe radii on the rehearsal and probe sets; compare Shirt recall and other-class recall with the global-radius version and with no table; then add exceptions until the damage budget stops it.
Success criterion: Shirt recall +2 points or more on the test set with no class down by more than 0.5 point; per-item radius at least as good as the best global radius chosen on the test set (the global-radius control uses the test set to pick r, which favours it).
Expected cost (ESTIMATED): 64 exceptions x (4,608 bits = 576 bytes + 4 bytes) = 37 KB; one query is 64 XOR-popcounts of 72 words = 4.6k word operations; the radii scan is 64 x 400 images x 72 words = 1.8 million operations. Uncertainty: this explains nothing ("why"); it only memorises where the model fails, and the paper's cache failed on complex inputs (Wikitext ES 0.001), so a 28 x 28 image may behave like the complex case. It is the cheapest baseline and should be run to know whether a clause-based explanation adds anything beyond stored cases.

### Recommended order
Run Design B1 first (one changed draw, plus the partner-pair counters) and Design D (cheapest baseline), because together they show whether the loop is needed at all. Then Design A (its counters are reused by B2 and C), then B2's injection test, and Design C only if A shows that accepted rules have a real gain. For all designs report paired fixes and breaks counts, not only accuracy, and report which controls (random clauses, random partner, no rules) were beaten.
