# Thinking research 3: "a guess about why" (hypothesis formation, testing and keeping)

Scope: how published work forms an explanation of a confusion ("class A and B differ because of this feature combination"), tests it on held data and keeps it only if it helps without hurting old knowledge. The aim is to learn from the papers and invent our own method, not to copy. All numbers in section (b) are AS REPORTED BY THE AUTHORS (not re-measured here). All numbers in section (d) are ESTIMATED or targets, nothing was run.

Rules respected (from `CLAUDE.md` and `PROJECT_MEMORY.md`): matrix-free (no dense matrix-vector products, no multipliers, no backprop in the chip); allowed are scans, counting tables, clauses (AND of literals), hash lookups, small state, local rules. Standing caution of 24 Oct 2026: no label at test time; labels may be used only in the learning phase, so the test of a rule on "held data" uses either a small labeled stored set or label-free signals on the unlabeled probe.

## Honesty about reading depth

No paper was read page by page. For each one below I downloaded the PDF, converted it to text and read the abstract, introduction, the method section and the main results and limitation sections; appendices, proofs and most secondary experiments were not read. So the column "read fully" is "no" for every row; "core" means those sections were read. Not read at all (named in the task but not obtained): CN2 and RIPPER (not on arXiv), query-by-committee (Seung et al. 1992, not on arXiv), the original abductive learning paper (NeurIPS 2019, not on arXiv; I read a 2025 follow-up instead), and the contrast pattern mining survey (arXiv 2209.13556, downloaded, abstract-level only through a search snippet). I found no paper that analyses Tsetlin machine clauses specifically for class confusions; a search returned only papers on feedback, clause size and coalesced clauses. That gap is itself a finding.

## (b) Per paper

### 1. Popper (learning from failures)
Mechanism: three stages. Generate a hypothesis (a logic program) that satisfies the current constraint set; test it against positive and negative examples; if it fails, turn the failure into constraints. Too general (covers a negative example) prunes all its generalisations; too specific (misses a positive) prunes all its specialisations; theta-subsumption makes "generalisation of" a cheap syntactic relation. One test therefore removes a whole region of the hypothesis space. The loop ends when a program entails all positives and no negatives, or no hypothesis is left. Named after falsification.
Key numbers (reported): on grid/robot/list tasks Popper beats Metagol and ILASP (ILASP3 learned nothing within the time limit even on the 10x10 grid); on one task about 40 times faster than "Enumerate"; the learning time does not grow with the domain size because the hypothesis space is independent of it. Does not handle noise (stated limitation; the proposed fix is to relax when constraints apply and keep the best hypothesis so far).
Transfers: (1) the two-sided failure logic: if a clause fires on a wrong-class example it is too general, so only specialise (add a literal); if it never fires on a positive, it is too specific, so only generalise (drop a literal). With clauses = AND of literals, subsumption is plain set inclusion of literal sets, a bitmask test. (2) A learned blacklist of literal sets (a bit-set or hash of failed clauses) so that one failure kills many candidates. (3) Optimal/smallest hypothesis first (short clauses before long). Does not transfer: ASP solver and Prolog (no matrices but heavy symbolic machinery); exact all-positives-no-negatives acceptance (pixel data is noisy, so we need a count threshold, which Popper lacks).

### 2. CORELS (certifiably optimal rule lists)
Mechanism: branch and bound over rule lists built from pre-mined frequent antecedents; objective is misclassification plus a length penalty. A lower bound on a prefix holds for every extension, so a prefix whose bound exceeds the best known objective is cut with all its extensions; further bounds: a rule must have a minimum support and a minimum number of correct predictions, a prior upper bound on list length, and a symmetry map that keeps only the best permutation of the same antecedent set. A prefix tree (trie) holds the state. Identical features with opposite labels give an unavoidable error bound.
Key numbers (reported): optimal list in seconds, optimality certified in about 10 minutes; 10-fold cross-validated accuracy better than or similar to CART and C4.5; on the recidivism data about as accurate as the proprietary tool.
Transfers: (1) the idea of a certificate: "no clause of this size can fix more than X" gives a stopping rule and an honest ceiling; for us the analogue is the unavoidable-error bound, counting identical codes with opposite labels among Shirt and T-shirt (a cheap hash-table count). (2) Minimum support and minimum correct count as hard filters before any test is run. (3) Length penalty in the objective. Does not transfer: exhaustive branch and bound over 4,608-bit codes (too large); needs pre-mined itemsets and a big queue.

### 3. Tsetlin machine (original)
Mechanism: each clause is an AND of literals chosen by a team of Tsetlin automata (one counter per literal; include if the state is in the upper half). Type I feedback (given when the clause belongs to the true class) pushes clauses to fire and to include literals that are 1 in the input, with probabilities (s-1)/s and 1/s from a table; Type II feedback (given when the clause belongs to the wrong class and fires) includes a literal that is 0 in the input, so that the clause stops firing: its stated purpose is "to introduce candidate literals that increase discrimination power". A summation target T limits how many clauses vote so that clauses spread over sub-patterns. The paper proves the equilibria of the game correspond to optimal propositional formulas.
Key numbers (reported): competitive with SVM, decision trees, random forests, naive Bayes, logistic regression and neural networks on five benchmarks (Iris, digits, noisy XOR with non-informative features, etc.); the digit "1" pattern is shown as a human-readable clause.
Transfers: this is already our clause learner; the useful reading is that Type II feedback is a built-in "why not": it adds exactly the literal that contradicts a wrong-class firing, so the set of literals Type II adds for a class pair is a ready-made, count-based answer to "what separates A from B". We can log, per ordered class pair, which literals Type II chose (a counter table), rather than only updating states. Does not transfer: it is a training rule, not a held-out test; it has no accept/reject step, no notion of damage to old knowledge, and updates are always applied.

### 4. Clause size constrained TM
Mechanism: once a clause has more literals than a bound b, only Exclude actions are reinforced (the Type I columns that reward inclusion are switched off), so oversized clauses appear only transiently. Type II is unchanged.
Key numbers (reported): the same accuracy with up to 80 times fewer literals; accuracy rises with shorter clauses on TREC, IMDb and BBC Sports, then falls gracefully toward one literal; also lower switching activity (power) in hardware.
Transfers: short clauses are the interpretable and the testable ones: a 3-5 literal clause has few degrees of freedom, so a small held-out set can reject it with some trust. We use b as the complexity budget of any proposed rule. Does not transfer: nothing, except that the paper does not analyse confusions either.

### 5. SSDPS (statistically significant discriminative patterns)
Mechanism: for two classes, a pattern is discriminative if its growth rate (support in D1 / support in D2), support difference or odds ratio is at least a threshold alpha, and it is accepted only if the lower end of the 95% confidence interval of that score is above a second threshold beta. The CI uses counts only: a = D1 with pattern, b = D1 without, c = D2 with, d = D2 without, standard error sqrt(1/a - 1/(a+b) + 1/c - 1/(c+d)) for growth rate. An enumeration order makes both scores usable for pruning.
Key numbers (reported): faster than SFP-Growth and CIMCP and outputs far fewer patterns; the worked example has growth rate 2.4 but a CI of 0.37 to 16.6, i.e. a high score can still be insignificant with little data.
Transfers: this is the best fit for "trustworthy with little data": the test is four counts per candidate, a log and a compare (the log can be a table). A candidate is kept only if the lower confidence bound clears a threshold. Does not transfer: the enumeration of all patterns (we propose greedily instead); the plain CI ignores multiple testing (we must charge for the number of candidates tried).

### 6. DreamCoder (wake-sleep program learning)
Mechanism: wake: search programs that solve tasks, guided by a neural recognition model, scoring by fit times prior. Sleep 1 (abstraction): replay solutions, find common sub-programs and add them to the library (a description-length prior favours short, reusable code). Sleep 2 (dreaming): train the recognition model on replays and on "fantasy" programs sampled from the library. So hypotheses are kept when they compress what was found, and the search prior improves with each kept item.
Key numbers (reported): learns about 20 list operations from 109 tasks, finds a sort program in under 10 minutes with 5 library calls where the raw-primitive version has 32 calls and would need an estimated 10^72 years of brute force.
Transfers: (1) keep a rule only if it is reused, i.e. if it explains several confused examples (compression test: a kept clause must cover at least m confusions); (2) dream-based testing: sample fantasies from the class bit-frequencies (our dreams) to test whether a rule fires on things that are not really that class. Does not transfer: neural recognition network, Bayesian marginalisation over refactorings (heavy, uses gradients).

### 7. STOKE (stochastic superoptimisation)
Mechanism: local search by Markov chain Monte Carlo over programs. A proposal changes one instruction or operand; the cost is correctness (distance to the target on test cases, which smooths the search) plus performance; accept if cheaper, accept a worse one with probability decreasing in the cost increase. Expensive symbolic validation is rarely used: candidates are first run on a small set of test cases (about 500,000 test-case executions per second), the full validation runs only when all tests pass, and a failed validation yields a counterexample that is added to the test set. The test set therefore grows exactly where the guesses were wrong.
Key numbers (reported): matches or beats gcc -O3 and in some cases expert hand-written assembly; symbolic validation is below 100 per second, which is why the cheap test cases come first.
Transfers: this is the cleanest model of our loop: local mutation, cheap test on a stored set, a costly confirmation, and a counterexample set that grows with failures. The cost as a graded distance (not just pass/fail) is useful: a margin gain on confused examples is a smoother signal than a flipped decision. Metropolis accept can be done with an integer temperature and an LFSR compare (no exp). Does not transfer: exactness (STOKE has a formal validator; we only have samples).

### 8. Deep Bayesian active learning with image data
Mechanism: acquisition functions that rank unlabeled points: maximum predictive entropy, BALD (mutual information between prediction and model parameters), variation ratios, mean standard deviation, versus random. Uncertainty over parameters comes from dropout sampling; each acquisition is computed from T stochastic forward passes.
Key numbers (reported): 5% test error on MNIST with 295 labels against 835 for random sampling; 1.64% error with 1,000 labels; all acquisition functions beat random on that model.
Transfers: "what to ask next" = pick unlabeled probe items with the most disagreement; our dual is already available without dropout: the margin between the top two class scores, and disagreement between two cheap views (fast table vs slow table, or two clause banks) as a query-by-committee substitute. Cost: one scan of the probe set. Does not transfer: Bayesian CNN and Monte Carlo dropout. Caution: the paper itself warns of querying noise rather than information; in our case the Shirt/T-shirt pixels are partly irreducible, so pure uncertainty keeps asking about the same undecidable items (see the CORELS bound).

### 9. Intrinsic curiosity module
Mechanism: curiosity reward = error of a forward model predicting the next state's features; the features come from an inverse-dynamics network trained to predict the action, so only aspects of the world the agent can influence enter the features and the unpredictable-but-irrelevant parts (leaves moving) are ignored.
Key numbers (reported): in VizDoom with sparse reward and in Super Mario with no extrinsic reward, curiosity gives exploration where plain agents fail; transfers to new levels.
Transfers: "surprise = prediction error" is already our write-on-wrong rule. The new idea is the feature filter: measure surprise only in features that help predict something we control (here: the class decision), which is the same idea as a pertinent-negative or invariance filter. Does not transfer: neural nets, policy gradients.

### 10. Random network distillation
Mechanism: bonus = error of a trained predictor against a fixed random network's output on the state; high on rarely visited states, falling with visits; unlike forward-dynamics curiosity it has no noisy-TV problem because the target is deterministic.
Key numbers (reported): state-of-the-art on Montezuma's Revenge at the time (finds more than half the rooms; occasionally completes the first level) without demonstrations.
Transfers: a hash-count novelty (a count-based version: the number of times this bit-pattern bucket was seen) is the matrix-free analogue of a visit-count bonus, and is deterministic, so the noisy-TV problem cannot arise. Use it to choose probe items that are new rather than merely uncertain. Does not transfer: the two networks.

### 11. Curriculum abductive learning (C-ABL)
Mechanism: abductive learning loops: the model predicts symbolic labels, abduction finds label sets consistent with a knowledge base, the best one by consistency optimisation becomes the supervision, retrain. The search over candidate explanations (the abduction space) explodes with a big knowledge base, so C-ABL splits the knowledge base into sub-bases by dependency and introduces them in phases, moving on when each label's accuracy passes a threshold; the paper analyses that this keeps the abduction space small and avoids forgetting between phases.
Key numbers (reported): better accuracy, speed and stability than earlier ABL variants on decimal and hexadecimal digit addition with images, and a chess task; the gap grows as the logic gets more complex.
Transfers: the control idea is useful: introduce hypotheses in order of dependence, simplest first, and only advance when the earlier ones pass. For us "knowledge base" = small hand-given constraints between classes (for instance "a Pullover has long sleeves; a T-shirt does not"), none exist yet. Does not transfer: first-order logic solvers; it needs a symbolic knowledge base that we do not have. The honest reading: abduction is a candidate generator constrained by background knowledge, and our only background knowledge is the counted statistics.

### 12. Contrastive explanation method (pertinent positives and negatives)
Mechanism: for an input classified as t, a pertinent positive is the minimal set of present features that alone keeps class t; a pertinent negative is the minimal set of absent features whose addition changes the class. Both are found by optimisation with a hinge loss on the class-score margin plus an L1+L2 (elastic net) sparsity term, and an autoencoder term to stay on the data manifold, solved by FISTA.
Key numbers (reported): on MNIST, a "3" is explained by the strokes present and by a small horizontal bar whose presence would make it a different digit; applied also to a procurement-fraud dataset and brain activity data; judged by humans (no accuracy number).
Transfers: for binary codes the optimisation is not needed: the pertinent negative for example x between predicted class A and runner-up B is the smallest set of bits to flip so that B's score exceeds A's. Since our scores are sums of counter values, each bit contributes a known table entry, so a greedy pick of the bits with the largest score difference (a sort over the table rows of the two classes) gives the flip-set with no gradient. Frequent flip-sets over many confused examples are the "why" rules. Does not transfer: FISTA and the autoencoder; the explanation is local to one example and explains the model, not the world (a rule that explains our table is not necessarily true of garments).

### 13. Counterfactual explanations (Wachter et al.)
Mechanism: the explanation is the closest point x' to x for which the model outputs another target y', found by minimising (f(x') - y')^2 plus a distance d(x, x'), where d is the L1 distance weighted by the inverse median absolute deviation of each feature to prefer few changed features; several different counterfactuals can be returned.
Key numbers (reported): none in the accuracy sense; demonstrated on LSAT and diabetes data, where the normalised L1 gives sparser counterfactuals than plain L2.
Transfers: confirms the greedy flip-set above (sparsity through L1 = counting changed bits) and the idea to return a few alternatives, not one. Does not transfer: gradient search over continuous features; the legal analysis is not relevant here.

### 14. Invariant risk minimisation
Mechanism: with data from several environments, look for a representation on which the same classifier is optimal in all of them; the practical form (IRMv1) adds a penalty equal to the gradient norm of the risk with respect to a dummy classifier scale. A feature that predicts the label in one environment only (a spurious correlation) is rejected.
Key numbers (reported): Colored MNIST: ERM 87.4 train / 17.1 test; IRM 70.8 / 66.9; optimal invariant model 75 / 75; grayscale oracle 73.5 / 73.0.
Transfers: the principle, without the gradient penalty: accept a literal/rule only if its contrast score has the same sign and a lower confidence bound above zero in every environment, where environments are cheap partitions available to us (stage 1 vs stage 2 of the stream, real vs dreamed images, image brightness quartiles, odd vs even sample index as a null test). This is a min-over-environments test, done with counts. Does not transfer: the penalty and the gradient; and environments in our data are a design choice, not given by nature. It also needs several environments for each rule to have a chance to fail.

### 15. MEND (model editing)
Mechanism: edits a model's behaviour on one input using a learned small network that transforms the fine-tuning gradient (low-rank). The paper's contribution that matters here is the evaluation protocol: edit success on the edited example and on its equivalence neighbourhood (paraphrases), and drawdown/locality on unrelated inputs; fine-tuning on the single edit overfits, hurting both locality and generality.
Key numbers (reported): on very large models MEND reaches edit success 0.81-0.88 on the editing tasks where fine-tuning gets 0.55-0.87 with far worse locality; multi-edit: with 25 simultaneous edits an alternative drops to 0.35 while MEND stays at 0.89.
Transfers: the three-set test for any rule: reliability (it fixes the confusions it was made for), generality (it fixes similar confusions not used in its construction) and locality (it changes nothing on unrelated inputs; measured by prediction flips on unlabeled probe data, which needs no label). Edits must be tested again when several are stacked, since interactions appear. Does not transfer: the gradient editor network and the weight matrices.

## (c) Synthesis

### The generic loop in the literature
1. Propose: draw a candidate from a structured space (Popper: program from ASP; STOKE: mutate one instruction; abduction: label set consistent with knowledge; TM: Type II chooses the literal; CEM / counterfactuals: smallest change that flips the output; contrast mining: the pattern with the largest growth rate).
2. Test cheaply on a stored set, with a graded score (STOKE's distance, CEM's margin hinge) rather than only pass/fail, because a graded score gives a gradient-free direction.
3. Constrain: use the failure itself to remove many candidates (Popper's generalisation/specialisation constraints, CORELS's prefix bound, STOKE's counterexample added to the test set).
4. Confirm with the expensive or independent check (STOKE's symbolic validator, CORELS's certificate, MEND's locality set).
5. Keep with a record (library growth in DreamCoder, the edit log), and prefer the shortest hypothesis (description-length prior, length penalty, clause size bound).

### What makes the test trustworthy with little data
- Use confidence bounds on counts, not point estimates (SSDPS: growth rate 2.4 had a CI from 0.37 to 16.6). Four counts and a log are enough.
- Separate the sets: one for proposing, one for testing, a third for the final confirmation; reuse of the test set by many candidates inflates the winner (STOKE reduces this by adding counterexamples; none of the papers charges explicitly for the number of candidates tried, so that must be our own addition: a per-candidate penalty or a stricter bound as the count of tests grows).
- Prefer short, high-support rules (CORELS minimum support; clause size bound); short rules have little room to fit noise.
- Require the evidence in more than one environment (IRM). Colored MNIST shows the failure it prevents: 87.4 train and 17.1 test for the shortcut.
- Use dreams and unlabeled probe data as a null set: a rule should not fire much where the class is not (DreamCoder fantasies, MEND locality).
- Know the ceiling (CORELS): identical codes with opposite labels bound the possible gain; a rule cannot reasonably claim more.

### How acceptance is guarded
Against overfitting: the confidence bound, complexity penalty and separate confirmation set above. Against hurting old knowledge: MEND's locality measure, rehearsal of stored old items, and an explicit budget. None of the 15 papers gives a ready-made damage budget for a classifier made of counting tables; MEND measures drawdown, CORELS bounds error, but neither says "stop accepting after X cumulative damage". Our counted veto rules already have a measured damage bound in the project, which is the closest existing piece. Reversibility (STOKE's chain can move back; our controller can undo a step) is the final guard and is cheap if each kept edit is logged with its previous value.

### What the literature does not give us
- No source ties together confusion statistics and clause analysis in a Tsetlin machine; Type II feedback is the only built-in discrimination mechanism and it is never reported per class pair.
- All strong guarantees (Popper optimality, CORELS certificate, STOKE validator) rest on noise-free data or exact checks; pixel data is noisy and some Shirt/T-shirt pairs are probably not separable by a 28x28 grey picture alone (project note: Shirt recall 63-74% is limit for picture-only; CNN ruler 79.4%). Expect a small ceiling.
- Active learning and curiosity pick what to ask next but do not generate a reason; the reason generators (contrast patterns, pertinent negatives) do not decide what to ask. Joining them is our job.

## (d) Our own method sketch

Common setting for all three: Fashion-MNIST with the current L code (4,608-bit codes), the clause banks and counting tables as shipped. Target pair: Shirt (S) against T-shirt/top, Pullover, Coat (call them T3). Baseline Shirt recall 0.5-0.67, L alone 0.638 (project figures). Primitives only: per-class bit frequencies and counts, popcount of ANDs, small counters, a stored rehearsal set (about 20 images per class), unlabeled probe images. Cost figures are ESTIMATED from operation counts; the codes are 4,608 bits = 72 words of 64 bits.

Shared bookkeeping ("rule ledger"): a table of kept rules, each with the literal set (a list of up to b = 4 literal indices), a type (boost S, veto T3-member), the class pair, the counts at acceptance (fixes, breaks, probe flips), the environment results and an undo record. Fixed size, for example 64 rules x 16 bytes = 1 KB. A second table, the "failure blacklist", holds a 32-bit hash of each rejected literal set, plus a flag too-general or too-specific, as in Popper.

### Design A: contrast counter proposes, Popper-style constraints and a lower-bound test keep

Candidate generation (all counting): run the doubt signal over the training stream; for examples of true class S (labels allowed in learning) whose margin shows doubt toward a T3 class X, add 1 to a pair-specific confusion count per code bit: n_conf[S,X][bit], and similarly n_ref[X][bit] from correctly decided X examples. For each literal (bit or its negation) compute growth rate with a counter-based log-ratio and its lower confidence bound from the four counts (as in SSDPS). Keep the top 16 literals with the lower bound above beta. Candidate clauses: greedily AND 2 to 4 of the top literals, choosing each new literal to maximise the count of confused S examples covered minus the count of X-correct examples covered (a scan over a few hundred stored examples; popcount of the AND with the clause mask).
Test: on a separate set B (confusion examples not used for proposing, plus the stored rehearsal images of all 10 classes): fixes = S examples whose decision flips to S when the rule adds +delta to S (or subtracts from X); breaks = examples of any other class that flip away from correct. Unlabeled probe: flip rate = share of probe items whose top class changes.
Accept if (i) the lower confidence bound of fixes/(fixes+breaks) is above 0.5 by a margin, (ii) breaks on any single other class are at most 1 on the rehearsal set, (iii) probe flip rate is at most the damage budget Bflip (for example 0.2% of probe items), (iv) the rule covers at least m = 5 confusions. A clause that fails by breaks gets a literal added (specialise) and the old set goes to the blacklist as too-general; a clause with zero fixes gets a literal removed and goes on the list as too-specific. Stop after K = 200 proposals or when 3 rounds in a row accept nothing.
Minimal experiment: train L as now; hold out 25% of the training Shirt/T3 confusions as set B; run the loop; evaluate on the 10,000 test images. Compare against (1) no rules, (2) the same number of random 3-literal clauses passed through the same test (tests whether the contrast proposal matters), (3) the project's current counted veto rules.
Success criterion: Shirt recall on the test set +3 points or more (0.638 to at least 0.67) with overall accuracy not lower by more than 0.2 point and no single class recall lower by more than 0.5 point; the random-clause control gains at most 0.5 point.
Expected cost (ESTIMATED): proposing about 4,608 x 3 classes counter updates per confusion example plus a 4,608-entry sort per round: below 10^6 operations; testing 400 stored images x 72 words = 29k word operations per candidate, 200 candidates = 6 million; ledger 1 KB, blacklist 1 KB. Seconds on a CPU; hardware cost is a counter array and an AND-popcount unit that exists already for clause evaluation. Uncertainty: the project's earlier result that counted vetoes are bounded but weak suggests the gain may be 1-2 points, below the target; the picture-only ceiling may bind. A null result (accepted rules exist but gain under 1 point) would itself be informative: it would indicate the missing evidence is not in the 4,608-bit code.

### Design B: flip-set explanation plus invariance test across environments

Candidate generation: for each confused example (decided A=T3 member, true S, runner-up S), compute its pertinent negative: sort the bits by the score change they would cause if flipped (difference of the two classes' counter values for that bit, from the tables), and take the smallest prefix of the sorted list whose flipping makes S win. This gives a flip-set of at most 8 bits per example. Count how often each bit appears in flip-sets across all confused examples (a 4,608 counter array, with the sign: present-needed or absent-needed). Bits that appear in many flip-sets form the explanation "S differs from X because of these bits"; the 3-4 most frequent form a clause.
Test (IRM-like, no gradient): define environments, for example (e1) examples seen in the first half of the stream, (e2) the second half, (e3) real images versus dreams, (e4) brightness quartiles. A candidate literal is kept only if its contrast sign is the same and the lower confidence bound is above zero in every environment; then the clause goes through the Design A acceptance on the stored set. A deliberate spurious literal (a bit forced equal to the label in the proposing set and independent of it in the test set, as colour in Colored MNIST) is injected as a control.
Minimal experiment: (i) injection test: 20 injected spurious literals among 100 candidates: the invariance filter must reject at least 90% of them while keeping at least 70% of the real candidates; (ii) the end-to-end test of Design A with the invariance filter in front, compared with Design A without it.
Success criterion: filter rejects at least 90% of spurious, and the filtered pipeline has at least as much Shirt recall gain as unfiltered with at most half the probe flip rate.
Expected cost (ESTIMATED): one pass over the confused examples with a table lookup per bit (4,608 x number of confusions, at most about 10^7 operations) and four counter sets; memory 4 x 4,608 x 2 bytes = 37 KB. Uncertainty: with few confused examples per environment (a few hundred) lower bounds will be wide and the filter may reject everything; the experiment shows the minimum sample needed. Environment choice is arbitrary; if brightness quartiles correlate with the real signal, the filter will throw it away.

### Design C: local hill climbing on the clause bank with a damage budget and an undo log (STOKE-like)

Candidate generation: mutate one thing in a Shirt or T3 clause bank: flip the include state of one literal (nudge a Tsetlin counter by one step in a clause chosen at random among those that fired on a confusion), preferring literals taken from Design A/B (a biased proposal) 70% of the time and random literals 30%. This is the STOKE mix of local and global proposals.
Cost function: C = (errors on the confusion test set, measured with the margin: sum over confusions of the hinge on the S-versus-X score gap) + lambda1 x (errors on the stored rehearsal set of the other classes) + lambda2 x (probe flip rate) + lambda3 x (literals in the clause). All integers, shift-scaled weights chosen as powers of two (no multiplies). Accept if C does not increase, or with a probability of 1/8 if it increases by at most 2 units, decided by an LFSR compare (threshold accepting; no exponential).
Guards: three test sets rotate (propose set, test set, confirm set); every 20 accepted edits run a confirm pass on the third set and roll back the last 20 edits if the confirm score is lower than at the previous checkpoint. Cumulative damage counter: the sum of breaks on rehearsal images since the start; the loop stops when it passes the budget (for example 0.3 point of total rehearsal accuracy). The undo record per edit is (clause id, literal id, old state), 4 bytes, ring buffer of 256 = 1 KB. Counterexamples (confusions that stay wrong after acceptance) are added to the test set, as STOKE grows its test set.
What to ask next: pick the next confusion examples from the unlabeled probe by lowest top-2 margin plus a hash-count novelty bonus, so the loop does not keep re-asking about the same irreducible items (the active-learning warning in paper 8; paper 10 for the count-based bonus). Labels for the chosen items are requested only inside the learning phase.
Minimal experiment: 2,000 mutations on the S/T3 banks, three seeds, with the same three controls as in Design A, plus a control where the biased proposals are replaced by random ones. Record accepted/proposed ratio, per-checkpoint rollbacks and cumulative damage.
Success criterion: Shirt recall at least 0.67 on the test set in at least 2 of 3 seeds, total rehearsal-set accuracy loss at most 0.3 point, and the biased proposal reaching that target in fewer mutations than the random one.
Expected cost (ESTIMATED): each proposal re-evaluates only the clause changed, on about 400 stored items: 400 x 72 = 29k word operations; 2,000 proposals = 58 million operations, plus the checkpoints, which is seconds on a CPU. Hardware: one AND-popcount unit, an LFSR, a 1 KB undo ring, a few counters. Uncertainty: with only a few hundred test items the climb will overfit the test set unless the rotation of three sets works; expect most apparent gains to disappear on the confirm set. The first thing to measure is therefore the gap between test-set and confirm-set improvement; if it exceeds about 1 point, the loop is fitting noise and must be given a stricter acceptance bound.

### Recommended order
Run Design A first (cheapest, and its counters are reused by B and C). Run Design B's injection test as a standalone check of whether the invariance filter works at this sample size. Design C is the full loop and only worth building after A shows that accepted rules have any real gain. For all three, report the paired fixes and breaks counts, not only accuracy.
