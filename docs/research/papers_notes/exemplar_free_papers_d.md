# Paper notes - continual learning in binary networks and why exemplar-free is hard

Scope: (a) class-incremental learning with binary / hyperdimensional / table-style learners; (b) why exemplar-free class-incremental learning (EFCIL) with discriminative features is hard. Read from arXiv PDFs on 25 Oct 2026. Numbers are copied from the papers (reported by the authors, not reproduced by us). Search found no arXiv paper on Tsetlin machine or logic-gate-network class-incremental learning with a real protocol (see "Not found / UNVERIFIED").

## 1. arXiv 2203.16588 - Constrained Few-shot Class-incremental Learning (C-FSCIL, CVPR 2022)

- **Mechanism.** Frozen feature extractor (ResNet-12 or a 5-layer CNN), meta-learned on the base classes only, then a fixed-size fully connected layer (d x d_f, d up to 512) that emits a hyperdimensional vector. An explicit memory (EM) holds one prototype vector per class. A query is scored by cosine similarity between tanh(g(f(x))) and tanh(p_i) for every stored prototype, so inference is a similarity search over the class vectors. Meta-learning uses a sharpened ("soft absolute") attention so that different classes map to quasi-orthogonal vectors.
- **Three update modes for a new class.**
  - Mode 1: prototype = mean of the k support vectors (k = 5), no gradient, written once to the EM.
  - Mode 2: sign() the prototypes to bipolar vectors, then retrain only the fully connected layer for T = 20 iterations so averaged activations match them. Needs a globally averaged activation memory (GAAM, one vector per class).
  - Mode 3: nudge the prototypes for U = 20 iterations (loss: penalise large pairwise cosine, stay close to the original prototypes), then retrain the fully connected layer as in Mode 2.
- **What is stored.** One d-dimensional prototype per class (EM); Modes 2 and 3 also one averaged activation per class (GAAM). No images and no per-sample features. Memory grows linearly with classes. Two key-prototype pairs can be superposed for 2x compression, costing 1.7 to 3.5 points on miniImageNet (appendix A.3).
- **Protocol: few-shot CLASS-incremental, task-agnostic** (single unified classifier over all seen classes, tested on all classes seen so far). miniImageNet and CIFAR100: base session 60 classes, 8 novel sessions of 5-way 5-shot (100 classes at the end). Omniglot: base 1200 classes, 9 novel sessions of 47-way 5-shot (423 novel, 1623 total).
- **Results.** CIFAR100 Mode 1: 77.47% in the base session, about 50% after the last session (100 classes); the table's per-mode columns were interleaved in the text extraction, so which mode gives which last-session value is UNVERIFIED. The paper reports all three modes beat the earlier FSCIL methods (CEC 49.14% last session, F2M 44.67%, AL-MML 29.37%). Omniglot: Mode 1 84.16% (base) to 81.56% (last); Mode 3 87.21% to 85.70%; stated accuracy drop of at most 2.6% (Mode 1), 1.4% (Mode 2), 1.6% (Mode 3) over the 423 added classes. Note that Omniglot is an easy, handwriting-character dataset.
- **Operations at update time.** Mode 1: a forward pass, a running mean, a memory write (adds and one divide; mean could be a counter). Modes 2 and 3: gradient descent on the fully connected layer, a floating-point matrix (limited to 20 steps). Inference: d_f x d matrix product plus a cosine against C prototypes.
- **Limitations.** (i) The feature extractor is never trained on novel classes. It works only because the base session is large and diverse (60 to 1200 classes) and the embedding was meta-trained to spread classes. On natural images the accuracy still falls from 77% to about 50% over 40 added classes. (ii) Needs k = 5 labelled samples per class and labels. (iii) Interference between prototypes rises with the class count; the paper counters it with d >= 256 and the Mode 2 and 3 tuning. (iv) Uses a dense matrix layer and floating-point cosine; not matrix-free. (v) Single run per setting as far as read; no variance reported in the main tables (UNVERIFIED for the appendix).
- **Fit to L.** High on the idea, low on the parts. Idea that fits: a new class costs one written vector and no gradient, with nothing overwritten (Mode 1), and a fixed binary / bipolar prototype space (Mode 2 bipolarisation). Parts that do not fit: the dense fully connected layer, the cosine with tanh, and the meta-learned CNN. It also shows the real cost: the old features were frozen, so new-class quality depends on how general the frozen features are.
- **Small test it suggests.** In L's existing counting code, freeze the deep binary-feature layers after a base session on 60 classes of CIFAR100 (or the digit sets L uses), then add classes 61 to 100 in 8 sessions of 5 classes with 5 samples each: for each new class store only an integer count vector (per-bit counts over the binary code of the k samples) and classify by Hamming or integer overlap. Report accuracy on all seen classes after each session; this is the exact C-FSCIL Mode 1 curve in integer form. Control: same run with a 10-class base session, to measure how much the result depends on base-session diversity.

## 2. arXiv 2409.18265 - Task-recency bias strikes back: Adapting covariances in Exemplar-Free Class Incremental Learning (AdaGauss, NeurIPS 2024)

- **Why in this note.** It is the clearest recent analysis of why EFCIL with a trainable feature extractor fails, and it gives measured numbers for the frozen-versus-trained trade-off.
- **Three observations (measured by the authors, ResNet18, ImageNet-Subset, 10 tasks).**
  1. If the feature extractor is trained on later tasks (unfrozen), the stored class means and covariances no longer match the true class distributions (representation drift). If it is frozen after task 1, the old distributions stay valid but classes of new tasks become inseparable (Fig. 1).
  2. Representational strength grows with each task, so the stored covariance matrices of early tasks have lower rank than those of recent tasks. When inverted (Bayes / Mahalanobis classification) the early-task matrices give larger norms because of numerical instability, which skews decisions towards recent tasks: task-recency bias at the representation level, with no linear head and no exemplars involved.
  3. Features suffer dimensionality collapse (covariance rank far below the 512 latent size), so covariances are not even invertible.
- **Method (AdaGauss).** Each class is stored as a Gaussian (mean and full covariance) in the latent space. After each task: train the feature extractor with cross-entropy plus an anti-collapse loss (keeps the diagonal of the Cholesky factor of the batch covariance above 1) plus projected feature distillation through a 2-layer MLP; then train an adapter network that maps old latent space to new using only current-task data, sample 10,000 points from each old Gaussian, push them through the adapter and re-estimate mean and covariance. Classification is Bayes (Mahalanobis).
- **What is stored.** Per class: S + S(S-1)/2 numbers (mean and covariance), S = 64 from scratch, 32 for fine-grained (about 2,080 numbers per class at S = 64). No images. Adapter and distiller are discarded after each task.
- **Protocol: CLASS-incremental, exemplar-free, task-agnostic.** CIFAR-100, TinyImageNet, ImageNet-Subset, 10 and 20 equal tasks, trained from scratch; CUB200 and FGVCAircraft with ImageNet-pretrained backbone, 5, 10, 20 tasks. Mean of 5 runs.
- **Results (last-task accuracy, from scratch, T = 10 / T = 20).** CIFAR-100: AdaGauss 46.1 / 37.8 versus EFC 43.6 / 32.2, FeTrIL 34.9 / 23.3, LwF 32.8 / 17.4, EWC 31.2 / 17.4. ImageNet-Subset: AdaGauss 51.1 / 42.6, EFC 47.4 / 35.8, LwF 37.7 / 18.6. Pretrained CUB200 T = 10: AdaGauss 55.8, EFC 51.0. For comparison joint training is far higher (not given in the main tables, UNVERIFIED). Ablation (CIFAR-100, T = 10): no mean adaptation 22.9 versus 46.1 full; nearest-mean classifier instead of Bayes 36.4 (9.7 points lower); diagonal covariance 41.1; no anti-collapse loss (shrinkage instead) 40.2. Frozen-extractor methods (FeTrIL, FeCAM, DS-AL) lose 12 to 16 points on ImageNet-Subset in the paper's comparison because new classes are not separable.
- **Operations.** Training on a GPU (SGD 200 epochs, adapter 100 epochs); inference needs a Mahalanobis distance (matrix multiply). Not matrix-free.
- **Limitations (authors').** Cross-entropy separates only the current task's classes, so old classes may begin to overlap each other and new classes in the latent space and are forgotten; open problem in EFCIL. Few samples per class make high-dimensional covariances impossible, forcing a small bottleneck that limits representation strength. Even the best method keeps only about 46% (CIFAR-100, 10 tasks, from scratch) after the last task.
- **Fit to L.** As an analysis it applies directly: a deep layer that is retrained while old classes are stored only as statistics will drift and the statistics go stale. Its remedies (covariance adaptation, MLP adapter, Cholesky loss) are dense-matrix and backprop based and do not fit L. The finding that supports L's design: freeze the deep feature layers once trained (no drift, no adaptation needed), and the remaining risk is separability of new classes. A second finding to keep: nearest-mean on mean-only statistics is clearly weaker than a classifier that uses spread (9.7 points here), so a count table that keeps per-bit variance or per-bit counts (more than a mean) is worth testing.
- **Small test it suggests.** Measure drift directly on L's feature layers: after training on classes 1 to 50, update the layer on classes 51 to 100 (with a frozen copy for comparison) and report how often stored per-class bit-count tables for classes 1 to 50 flip their top-1 on held-out classes 1 to 50 (stale-statistics error), versus the frozen-layer copy. Also report the recent-class bias (fraction of old-class test samples assigned to new classes), which is the task-recency measure.

## 3. arXiv 2010.15277 - Class-incremental learning: survey and performance evaluation on image classification (Masana et al., TPAMI)

- **Mechanism (taxonomy).** Three families: regularisation (weights: EWC, PathInt, MAS, RWalk; data/activations: LwF, LwM), rehearsal with exemplars (iCaRL, EEIL, BiC, LUCIR, IL2M), and bias correction. The survey names four causes of forgetting in class-IL: weight drift, activation drift, inter-task confusion (classes from different tasks are never trained jointly, so no layer can separate them optimally), and task-recency bias (classifier outputs of separately learned tasks are not comparable; confusion matrices show images misclassified as the most recent task). The last two exist only in class-IL because there is no task id at test time.
- **What is stored.** Exemplar-free methods: nothing beyond the model (some freeze old output weights). Rehearsal methods: a fixed memory (for example 2,000 exemplars) or 20 per class.
- **Protocol: CLASS-incremental and task-incremental both, compared directly.** Main table: CIFAR-100 split 10/10, ResNet-32 from scratch; other settings include 11/50-5 and ImageNet.
- **Results (Table 2, average accuracy after task 2 / 5 / 10, CIFAR-100 10/10, no exemplars).** Task-IL: finetuning 59.8 / 49.8 / 38.3, LwF 72.0 / 76.7 / 76.6, EWC 61.5 / 60.2 / 56.7. Class-IL (the same methods, no task id): finetuning 38.2 / 18.6 / 10.1, LwF 55.4 / 41.6 / 30.2, EWC 39.8 / 21.9 / 13.1, PathInt 41.2 / 23.5 / 13.6. So removing the task id costs LwF 46 points at task 10 (76.6 to 30.2). With 2,000 exemplars (fixed memory) class-IL finetuning reaches 37.9 at task 10 (versus 10.1 without), and adding LwF or EWC regularisation on top of exemplars was worse than plain finetuning with exemplars (LwF-E 30.8, EWC-E 28.1). Bias-correction methods (CIFAR-100 5/20, 2,000 exemplars) end at 40.9 (FT-E), 43.5 (iCaRL), 45.7 (BiC), 45.6 (IL2M), 47.3 (LUCIR), 47.6 (EEIL).
- **Conclusions (authors').** Exemplar-free methods currently cannot compete with exemplar rehearsal and should be compared separately; data regularisation beats weight regularisation in the exemplar-free case; methods that explicitly address task-recency bias do better; network architecture (skip connections) matters a lot.
- **Operations.** All methods are gradient-trained deep networks; no hardware cost analysis.
- **Limitations.** Image classification only, 2020 methods only (before the Gaussian and prototype EFCIL methods such as AdaGauss), small CIFAR-scale networks for the main table, no binary, table-based or HDC learner. The exemplar-free gap is shown but not explained mathematically.
- **Fit to L.** Supplies the baseline L must beat: exemplar-free class-IL with a trained, shared deep network gives 10 to 30% on CIFAR-100 over 10 tasks, near the finetuning floor in the worst cases. This strengthens L's rule of freezing deep layers and growing only per-class count tables, because the four listed causes of forgetting all disappear for a frozen layer except inter-task confusion (classes never seen jointly) and recency bias in the table read-out.
- **Small test it suggests.** Reproduce the Table 2 shape on L: class-IL curve with a per-class count table classifier on frozen binary features, 10 tasks of 10 classes on CIFAR-100, reporting accuracy after tasks 2, 5, 10 and the task-confusion matrix. Then add a per-class normalisation of the table scores (divide by class sample count) and check whether the recency / count bias in the confusion matrix disappears.

## Implication for L

1. Frozen features plus per-class stored statistics is the one design with a documented, small, gradient-free cost for a new class (C-FSCIL Mode 1, one prototype per class). Its weakness is feature quality for unseen classes, which L must show on its own binary feature layers.
2. Retraining shared deep layers without old data causes drift, rank collapse and recency bias (AdaGauss, Masana); fixes in the literature are dense-matrix and backprop based and do not fit L.
3. Keep spread information (counts per bit, not only a mean) in the per-class table and normalise per-class counts to avoid the recency / count bias.
