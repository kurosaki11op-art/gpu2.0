# The ternary language model project (context given by the founder, 31 Oct 2026)

**Source of everything in the first three sections: the founder's own account and a screenshot of that project's honest results (from another project folder, `SpikingBrain-study\L-architecture`, not in this repo). I have not read its code or data.** The statements about datacentres (a water-cooling cycle that avoids evaporation, a cloud company short of electricity for its GPUs) are from videos the founder saw and are **not verified here**; the underlying point, that power and cooling limit datacentre growth, is widely reported.

## Why it exists (founder's reasoning)

Today's transformers are strong but dense; self-attention is the suspected main cost. Large computation, high current, heat, large training and stored weights cannot be fixed by a chip alone; the model must change too. Replacing multiplications and matrices inside current models makes them break, so the founder designed a new ternary model meant to run efficiently on a GPU. Its training costs more than twice a transformer's, and many runs failed.

## Honest results (founder's summary, transcribed)

| | result |
|---|---|
| **won** | text quality: the 5.5M-parameter ternary model scores 1.53 bits per byte (3 seeds) and beats the dense 1.7M model at 1.62; the 12.9M ternary model 1.529 (1 seed); the comparison is not fair because the larger dense models trained poorly; a Rust engine reproduces the Python scores to 4 decimals; reversed questions answered 100% at toy level when the digits appear exactly in the stored fact (it fails to refuse unknown numbers 16 to 47% of the time) |
| **close** | memory damage to text (best setting +0.028 to +0.035 drift against a +0.030 target; recall about 0.85 to 0.88 after writing, 0.54 to 0.58 in new surroundings); reworded questions (96% right with familiar attribute words, 52% with new ones; never answers about unknown entities); a fact store that refuses unknown keys (74 to 80% correct, 1 to 5% false answers) |
| **failed** | instruction following (the 1.7M dense model 21 to 58% on seen wordings, 0 to 7% on new ones); copying a retrieved fact through the network (0% so far); writing reverse facts into the network memory (7% at 200 facts); a hybrid test (one run crashed out of GPU memory, one stalled for about 15 hours); scaling did not fix memory drift |

## Literature check (30 Oct to 31 Oct 2026, web search; figures are from the papers' summaries, not re-derived)

- **Matmul-free language modelling** ([Zhu et al., arXiv 2406.02528](https://arxiv.org/pdf/2406.02528)): ternary weights, no matrix multiplication; the paper builds an FPGA accelerator whose ternary-add datapath is the power-efficient part and reports a Loihi 2 mapping at about 8 times human-readable throughput at 4.2 W; the FPGA wattage itself was not confirmed by the search (read the paper's Section 5 and Table 2 before quoting it).
- **BitNet b1.58** ([Ma et al., arXiv 2402.17764](https://arxiv.org/pdf/2402.17764)): ternary weights; the 3.9B model edged a 3B full-precision LLaMA on zero-shot tasks (51.2% against 49.7%); the large energy ratios in the paper are mostly modelled from operation counts, and training still needs full-precision weights.
- **Copying and recall** ([Jelassi et al., arXiv 2402.01032](https://arxiv.org/abs/2402.01032)): models with a fixed-size memory are limited at copying and retrieval; the suggested fix is a hybrid with an attention-like retrieval mechanism, and later work finds hybrids close most of the gap.

## Reading

1. The idea is current research, not a decade old; what separates the founder's models from the cited ones is scale (billions of parameters on large clusters) and training budget, not the direction.
2. The failures cluster on **exact recall** (copying a fact, reverse facts, refusing unknown keys), the known weakness of models without attention; the known remedy is an exact-recall mechanism, and the founder already built a **fact store**.
3. This repo's recognition algorithm (counting tables, lookups, adds only, a confidence flag) is the same family of mechanism: adds and lookups instead of matrix products. A language model made of ternary adds for compute and an exact lookup memory for recall, on hardware that is small SRAM plus adders, is a coherent joint target.
4. Energy claims in this literature are mostly modelled. A measured energy per generated byte on a real device, with a quality-matched dense baseline, is rare and would be a real contribution.

> **Founder's decision, 31 Oct 2026: the ternary language model was given as context only; it is NOT being worked on here, and the plan below is not pursued. This repo continues with the chip.**

## Proposed joint plan (not pursued, see the decision above)

1. **Measure first (needs the USB meter, due 1 Nov 2026):** run the ternary model's inference engine on the ESP32 (the founder's Rust engine exists; a C port is the likely route) next to a dense model of equal text quality, and measure energy per generated byte; bar written before the run.
2. **Model the hardware cost** of the ternary model at its real sizes (5.5M and 12.9M parameters, about 1.4 MB and 3.2 MB at 2 bits, which fit in on-chip memory) with the same kind of cheap model as [target 3](../new_start/step1_lm_result.md), using its real dimensions.
3. **Attack the recall failures with an exact lookup memory** inside the model path, not only beside it, and re-run the failed hybrid test on a machine with enough GPU memory.
